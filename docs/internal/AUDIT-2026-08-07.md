### Три вещи, которые вылезли на дне 2

**Из слоя нельзя выйти изнутри файла.** `.inst-shell-nav-toggle { display: none }`
не мог перебить `.inst-btn { display: inline-flex }`: `layout.css`
импортирован как `layer(kit.layout)`, а кнопка объявлена в `kit.components`,
и **порядок слоёв бьёт специфичность**. Вложенный `@layer kit.components { … }`
внутри `layout.css` не спасает — импорт в слой вкладывает всё содержимое,
получается подслой `kit.layout.kit.components`. Правило переехало в
`components.css`, а в ките появился **второй `@media`** — на том же пороге.
Утверждение «единственный `@media`» исправлено в трёх местах.

**`docscheck` принял имя слоя за класс.** `@layer kit.components {` дала
несуществующий `.components`, и он выглядел как настоящая находка «класс без
страницы». Инструмент починен: строки, начинающиеся с `@`, — не селекторы.
Ложное срабатывание в проверке дороже пропуска: пропуск ищут, ложному верят.

**Переходы в этой среде не проигрываются.** Панель браузера скрыта, кадры не
композитятся, поэтому `transition` навсегда остаётся в стартовом значении, а
`setTimeout` не помогает. Полчаса ушло на ложный диагноз «правило не
работает». Проверять анимированные состояния здесь можно только с
принудительным `transition: none`.

### Два наблюдения, добытых самой починкой

**`color-mix` не композитит.** Первая версия правки липкой колонки смешивала

## 1. Печать в двух из шести тем даёт белое по белому

`src/print.css:18` сбрасывает `color-scheme` только для `:root` и
`[data-theme="dark"]`. Но `dark-soft` и `dark-light` переопределяют
`--surface-*` **прямым присвоением шага рампы** (`src/tokens.css:399-437`), а
не через `light-dark()`. Смена `color-scheme` их не отменяет.

Замерено на живой странице в теме `dark-soft` с применённым правилом печати:

```
color-scheme: light          ← правило сработало
--surface-page  oklch(0.196) ← осталось тёмным
--surface-raised oklch(0.242)
--text-primary  oklch(0.978) ← белый
```

**Почему больно.** «Данные уйдут в печать» стоит на странице таблицы как
причина брать `<table>`. Браузер по умолчанию не печатает фоны — значит
получается белый текст на белой бумаге, то есть пустой лист. Печать заявлена
как фича (`README:111`, отдельный слой, 88 строк CSS) и не работает в трети
тем.

**Как у зрелых.** Тема — это набор значений, а печать — это переключение
набора, а не одного флага. Carbon и Spectrum держат печатную тему отдельным
набором токенов и не полагаются на `color-scheme`.

**Как чинить.** В `print.css` вернуть пять поверхностей и `--track` к светлым
значениям для всех тёмных тем:

```css
:root, [data-theme] {
  color-scheme: light;
  --surface-sunken: var(--n-2); --surface-page: var(--n-1);
  --surface-raised: var(--n-0); --surface-overlay: var(--n-0);
  --surface-field: var(--n-1);
  --accent-text: var(--a-5); --ok-text: var(--ok-5);
  --warn-text: var(--warn-5); --err-text: var(--err-5);
  --track: oklch(0 0 0 / 0.10);
}
```

Иначе — вынести переопределения тем в один блок, который печать гасит целиком.

**И сразу проверку:** `contrast` умеет резолвить токены — добавить
седьмую «тему» `print` и прогнать по ней те же 82 пары. Тогда это не
повторится.

примера: читатель решает, что сломан кит.

```html
<button class="inst-btn" type="button" onclick="dlg.showModal()">Удалить прогон</button>

```

`onclick` в примере допустим — он и есть та «одна строка JS», которую
конституция уже разрешила для `showModal()`. Либо добавить в `demo.js`
десять строк: делегированный обработчик `[data-open]`.

**Проверку — в сборку.** Скрипт обхода 140 примеров написан и работает

## 5. Мобильная навигация справочника не работает

Замерено на 390px после нажатия бургера:

```
aside            display: block, 375×671, overflow: auto hidden
.inst-nav        flex-direction: ROW      ← от @media кита
.inst-nav-label  display: none            ← от @media кита
самый правый пункт навигации: x = 7892px
```

Кит на `width < 60rem` (`src/layout.css:107-130`) превращает боковую колонку
в горизонтальную ленту. Сайт на той же ширине прячет её и открывает бургером
как **вертикальную панель** (`docs.css:277-286`). Два решения накладываются:
получается вертикальная панель, внутри которой навигация выложена в строку
длиной 7892px, без названий разделов.

**Почему больно.** На телефоне справочника нет. Совсем. Семьдесят один пункт
в горизонтальной ленте без групп — это не «неудобно», это неработающая
навигация. И это первое, что делает человек, которому прислали ссылку.

Вторая часть: без JS бургер не переключает `aria-expanded`, а колонка
`display: none` — **на мобильном без JS навигации нет вообще**.

**Как у зрелых.** Radix, Mantine, Carbon: на узком экране боковая колонка
уезжает в `<dialog>`/шторку во всю высоту, сохраняя вертикальный список и
заголовки групп. Горизонтальная лента годится для 5–8 пунктов, не для 71.

**Как чинить.**
1. В `docs.css` внутри `width < 60rem` вернуть вертикаль явно:
   `.inst-shell-aside .inst-nav, .inst-nav-group { flex-direction: column }`,
   `.inst-nav-label { display: block }`.
2. Лучше — переписать мобильное меню на `.inst-sheet` (он уже есть в ките и
   работает без JS через `<form method="dialog">` + одну строку `showModal`).
   Заодно это станет седьмым живым примером шторки, которая сейчас пустая.
3. В ките: правило `width < 60rem` для `.inst-shell-aside` **годится не всем
   приложениям**. Сделать его вариантом (`.inst-shell--rail`), а умолчанием
   оставить шторку или простое `display: none` + слот под кнопку.

**P0**

## 7. Поиск не находит компоненты ни по классу, ни по латинскому имени

Прогнал реальный алгоритм из `docs.js:141-157` по реальному `search.json`:

| Запрос | Что вернулось |
|---|---|
| `inst-btn` | **ничего** |
| `dialog` | Approval, Banner, Form, Popover, Sheet — **страницы «Модалка» нет** |
| `popover` | Меню, Тултип — **страницы «Поповер» нет** |
| `sparkline` | Легенда, Мера, Метрика — **страницы «Спарклайн» нет** |
| `table` | 8 страниц, **среди них нет «Таблицы»** |

Две причины, обе в генераторе:

1. `site/internal/content/content.go:172-177` — `plainText` **вырезает все
   блоки кода и весь инлайновый код** регуляркой ` ```…``` ` и `` `…` ``.
   Имена классов живут именно там. То есть индекс сознательно выбрасывает
   ровно тот текст, по которому ищут.
2. `site/internal/render/render.go:157-161` — тело режется до **1200 байт**
   (≈600 кириллических знаков, примерно два абзаца). Всё остальное содержимое
   72 страниц в индекс не попадает.

**Почему больно.** Документация на русском, API на английском. Единственный
мост между ними — поиск, и он этот мост не строит. Человек, который знает
`.inst-badge` и хочет найти его страницу, не найдёт её. Роадмап называет
поиск обязательным на 200 классах (`ROADMAP:3.3`) — он есть и не работает по
назначению.

**Как чинить.**
1. Индексировать **имена классов, токенов и data-атрибутов отдельным полем**
   с высоким весом: `instRe` из `docscheck` уже умеет их доставать.
2. Убрать лимит 1200 байт или поднять до размера страницы. Индекс сейчас
   93 КБ (в роадмапе написано 53 — цифра устарела); полный будет ~250 КБ,
   это одна картинка. Грузится лениво по первому запросу — цена нулевая.
3. Резать по рунам, а не по байтам (`b[:1200]` рвёт UTF-8; `encoding/json`
   молча ставит U+FFFD).
4. Добавить синонимы в frontmatter: `dialog` → «Модалка», `popover` →
   «Поповер». Пять минут работы, снимает 80% промахов.

## 8. Липкая первая колонка становится полупрозрачной

`src/components.css:1093-1098` красит липкую колонку в `--table-head-bg`
(специфичность 0,2,1). Правила наведения и выделения строки объявлены выше и
специфичнее — `src/components.css:577` (0,2,3) и `:580` (0,3,3) — и выигрывают.
А их значения **полупрозрачны**.

Замерено:

```
обычная строка, липкая колонка:  oklch(0.994 0.002 75)      непрозрачно
выделенная строка, липкая колонка: oklab(… / 0.14)          ПРОЗРАЧНО
```

Под колонкой при горизонтальной прокрутке едет содержимое — и просвечивает.
Собственный комментарий на `:1092` говорит: «Фон обязателен, иначе под ней
просвечивает уезжающее содержимое». Ровно это и происходит.

**Как чинить.** Прижать фон липкой колонки победившим селектором и
**складывать** состояние поверх непрозрачной базы:

```css
.inst-table--sticky-col tbody tr :is(th, td):first-child {
  background: var(--table-head-bg);
```

## 10. Немодальный `<dialog>` блокирует прокрутку всей страницы

## 15. Что `contrast` не ловит — важнее того, что ловит

492 пары в 6 темах — лучший инструмент такого рода, что я видел в проекте
такого размера. Слепые зоны:

2. **Состояния через `opacity` не проверяются.** `[data-state="skipped"]`

5. **Ни одной пары в режиме печати** (см. 1).

`contrast` резолвит `light-dark()`, `color-mix()` и `oklch()` сам — добавить
пятую «тему» `print` и шестую ось «перепад поверхностей» стоит по 20 строк.

## 16. Плотность перенастраивает половину кита, а не всё

Заявлено: «один атрибут на панели перенастраивает всё внутри неё»

## 18. Поиск сайта немой для скринридера

`site/internal/render/templates/page.html:76-80` + `docs.js:127-175`.
Проверено в браузере:

```
role                 нет
aria-expanded        нет
aria-controls        нет
aria-autocomplete    нет
aria-activedescendant нет
```

При этом на контейнере результатов стоит `role="listbox"`, а на пунктах —
`role="option"`. Стрелками двигается `aria-selected`, но фокус остаётся в

**Почему больно.** Это ровно тот грех, за который конституция ругает

своём главном интерактивном элементе.

`aria-activedescendant` на пункт, `aria-live` на счётчик результатов. Двадцать
строк. И это должно стать эталонным примером для будущей страницы
`/components/inputs/combobox`.

## 19. Кнопка «копировать» ломается при двойном нажатии

`docs.js:192-203`:

```js
const was = btn.textContent;     // клик 2 в пределах 1400мс: was = "скопировано"
btn.textContent = 'скопировано';
setTimeout(() => { btn.textContent = was; }, 1400);
```

Второй клик до истечения таймера навсегда оставляет подпись «скопировано».
Плюс `btn.setAttribute('aria-live','polite')` **в момент изменения текста** —
live-регион, созданный одновременно с изменением, не озвучивается. Плюс
`navigator.clipboard.writeText` без `catch`: на не-secure origin (LAN по http)
промис отклоняется, подпись не меняется, ошибка в консоли.

**Как чинить.** Держать исходную подпись в `dataset`, чистить предыдущий
таймер, `aria-live` объявить в разметке заранее, обернуть в `try/catch` с
запасным `document.execCommand`.

## 21. `aria-disabled` + `pointer-events: none` не блокирует клавиатуру

`src/layout.css:388` (`.inst-pager-item`), `src/overlay.css:130`
(`.inst-menu-item`), `src/data.css:274` (`.inst-calendar-day`).

`pointer-events: none` снимает мышь. Ссылка с `href` остаётся в порядке обхода

**Как чинить.** В контракте разметки записать: у отключённой ссылки убирается

## 22. Тултип не проходит WCAG 1.4.13

`src/overlay.css:160-181`. `pointer-events: none` на самом тултипе, показ
только по `:hover`/`:focus-within`, закрытия по Escape нет.

Критерий 1.4.13 (Content on Hover or Focus, AA) требует три вещи: **hoverable**
(курсор можно увести на сам тултип), **dismissible** (Escape), **persistent**
(не исчезает сам). Не выполняется ни первое, ни второе.

Плюс нет задержки появления: тултип вспыхивает при любом проезде мышью.

**Как чинить.** Убрать `pointer-events: none`, добавить `transition-delay` на
появление (300–500мс) и нулевую на исчезновение. Escape без JS не сделать —
записать в контракт разметки честно, как записана клавиатура.

хвост описывает несуществующее прошлое, теряет это право.

**Как чинить.** Числа — из машины, а не из головы: `contrast` и `docscheck`
уже печатают их, пусть генератор подставляет в страницу. Хвост конституции
«Что пока не сделано» — удалить, его работу делает роадмап.

## 30. `index.html` — второй источник истины на 141 КБ

- Покрывает **250 из 267** классов (17 не показаны).
- **Не проверяется `docscheck`** — тот читает только `docs/`.
- Содержит прямое нарушение конституции: `index.html:1427-1429` — аватары
  раскрашены **категориальной палитрой графиков** через **инлайновый стиль как
  канал оформления**. Запрещено дважды: «категориальный цвет не появляется вне
  графика» и «в живой спецификации запрещён инлайновый стиль как канал
  оформления». Плюс `--accent-on` (белый) на `--chart-3`/`--chart-5` контраст
  не держит.

**Вердикт по вашему вопросу** («дыра в правиле или дефект спецификации»):
**дефект спецификации.** Правило верное. Аватару нужен свой набор тонов — не
статусный (это не состояние) и не графический (это не ряд). Либо аватар
остаётся нейтральным (как в `data.css`), либо в токены заводится
`--entity-1…6` — отдельная ось «различить сущности», честно объявленная в
конституции. Второе лучше: аватары, теги пользователей и цвета лейблов —
одна и та же задача, и она у вас точно возникнет.

**Что делать с `index.html` вообще.** Решение оставить его принято. Тогда
он обязан попасть под `docscheck` — иначе через три месяца это будет файл,
демонстрирующий кит трёхмесячной давности.

## 31. `docscheck`: «покрытие 100%» — слабая метрика

Класс считается задокументированным, если строка `inst-foo` встретилась в
любом `.md`. Упоминание в таблице «Связанное» засчитывается наравне с
разделом и живым примером. 100% здесь означает «ни один класс не забыт», а
не «каждый класс объяснён» — и в README это подано как второе.

**Как чинить.** Три уровня вместо одного: упомянут / имеет свой раздел /
имеет живой пример. Сегодня третий уровень — 250/267 в `index.html` и
неизвестно сколько на сайте.

## 32. Нет CI, нет тестов, нет `.github/`

Три проверки существуют и запускаются руками. Ни одна не защищает `main`.
Всё, что найдено выше, могло быть поймано машиной — и не было.

## 33. `demo.js` меряет весь документ на каждое движение мыши

`demo.js:18-25` обходит `document.querySelectorAll('body *')` и берёт
`getBoundingClientRect()` у каждого. `:47-50` вешает это на `pointerover`,
`focusin`, `click`, `keyup`, `toggle`, `transitionend` **в фазе захвата**, по
три таймера на событие. Замер: 1.9мс на три прохода по 361 элементу.

Не смертельно, но проезд мышью по примеру генерирует десятки принудительных
пересчётов раскладки. `pointerover` в этом списке лишний — тултип можно
покрыть `transitionend`, который уже есть.

## 35. Порядок слоёв относительно чужих слоёв не документирован

`@layer kit.tokens, …` объявляется первым **в своём файле**. Если приложение
использует Tailwind (`@layer theme, base, components, utilities`), итоговый
порядок зависит от того, чей `@layer` браузер увидел раньше. Загрузили кит
первым — утилиты Tailwind выигрывают; загрузили вторым — `.inst-btn`
выигрывает у `mt-4`, и человек два часа ищет причину.

Обещание «стили приложения всегда выигрывают без `!important`» верно только
для **неслоёных** стилей. Приложение со своими слоями — самый частый случай
2026 года.

**Как чинить.** Абзац в README: «подключайте `kit.css` **до** своих
слоёв» + пример явного объявления порядка на стороне приложения.

## 36. Нет «изолированного» режима

Кит переопределяет `body`, `a`, `h1–h6`, `code`, `kbd`, `hr`, `button`,
`input`, `*` и `::-webkit-scrollbar`. Для ваших проектов это плюс. Для
человека, который хочет попробовать кит на одном экране существующей админки,
это «подключил — поехала вся страница».

**Как чинить.** Второй входной файл `kit-scoped.css`, где `base.css` обёрнут в
`.inst-root`. Это тридцать строк и снимает главный барьер пробы.

# Чего нет из того, без чего кит не самодостаточен

Ниша выбрана правильно, гонку за числом компонентов вести не надо. Но
«полностью покрыть потребности админок и дашбордов» сегодня не выполняется.
По убыванию частоты в реальных админках:

**Блокеры (без них экран не собирается):**

| | Почему обязателен |
|---|---|
| **Тост / очередь уведомлений** | `--z-toast` объявлен и не используется. Без него результат любого действия сообщать нечем |
| **Комбобокс с поиском** | Выбор из 200 вариантов — половина форм админки. `<select>` не подходит |
| **Выбор даты** | Календарь есть статический. Диапазон дат — основной фильтр дашборда |
| **Сплит-кнопка и кнопка-меню** | Собирается из имеющихся частей, нужна только документация композиции |
| **Панель массовых действий** | Выбор строк есть, действия над выбранным — нет |
| **Полоса фильтров с чипами** | Тег есть, ввод тега и снятие фильтра — нет |
| **Страница ошибки и верхняя полоса прогресса** | Числятся в SCOPE, не сделаны |

**Сильно облегчают (второй заход):**
командная палитра · раскрывающиеся строки таблицы · изменение ширины колонок ·
виртуализация · загрузка файлов со списком и прогрессом · сворачиваемая
боковая колонка (rail) · перетаскиваемые разделители · график с осями ·
точка-счётчик на иконке · редактирование по месту.

**Правильно отложено:** карусель, рейтинг, второй акцент, паритет с Ant Design.

# Оценки

Честные, с одной строкой обоснования. Шкала — «относительно того, чем это
хочет стать»: публичного кита, на который можно посадить чужие проекты.

| Направление | Оценка | Почему |
|---|---|---|
| **Кит как CSS** | **8** | Ярусы, слои, `light-dark()`, шесть тем через три ручки — сильнее большинства. Минус два: половина отступов мимо яруса ролей, и три реальных бага в таблице и оверлеях |
| **Полнота и API** | **5** | Агентный слой уникален и это настоящий дифференциатор. Но нет тоста, комбобокса, дейтпикера и массовых действий, а `.inst-stack` растягивает всё, что в него положат |
| **Доступность** | **5** | Контраст образцовый и проверен машиной; `forced-colors` и `reduced-motion` сделаны лучше, чем у большинства. И при этом цель 10×10, тултип не проходит 1.4.13, роли объявлены без поведения, поиск сайта немой |
| **Документация** | **7** | 72 страницы одного шаблона с «когда НЕ использовать» и разделом «Доступность» — редкость даже у больших. Минус: дубль подписи на 70 страницах, два пустых примера, битые иконки, четыре обещанных раздела отсутствуют |
| **Сайт справочника** | **4** | На десктопе хорош и быстр. На мобильном навигации нет, шапка переполняется, поиск не находит компоненты по имени класса — три поломки на трёх главных сценариях |
| **Инструменты и проверки** | **6** | `contrast` — лучшее, что я видел в проекте этого размера, `docscheck` полезен. Но **ни одна находка P0 не была бы поймана ими**, а CI нет вовсе |
| **Проект целиком** | **4** | Нет версии, нет CHANGELOG, нет CI, нет тестов. Четыре документа расходятся в цифрах, конституция перечисляет сделанное как несделанное |
| **Готовность отдать людям** | **3** | Технически можно склонировать. Практически: без версии, без установки, без темизации и без работающего поиска — второй человек не начнёт |

Среднее 5.3. Разброс 3–8 по-прежнему важнее среднего, и он тот же, что был:
**дорогая часть сделана, дешёвая — нет.** Это по-прежнему хорошая позиция.
