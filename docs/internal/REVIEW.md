# instrument — ревизия

Ревизия по состоянию на 2026-08-05. Все числа контраста посчитаны из
oklch-значений `tokens.css` (oklch → sRGB → WCAG 2.1), все баги каскада
подтверждены замером в браузере, а не выведены из чтения кода.

---

## 0. Резюме

Кит написан лучше, чем 90% того, что называют дизайн-системой. `DESIGN.md` —
не декоративное вступление, а работающая конституция: почти каждое правило в нём
защищает от конкретной ошибки, а не выражает вкус. Двухслойные токены, плотность
как атрибут контейнера, «завершённые задачи отступают, а не гаснут», «неопределённый
прогресс — отдельный вид полосы», «единица мельче числа» — это уровень человека,
который делал инструментальные интерфейсы, а не насмотрелся дриббла.

Поэтому и разбор жёсткий: к киту, который сам себе выписал законы, справедливо
предъявлять его же законы.

Три главных вывода — ниже. Дальше по разделам: подтверждённые баги, контраст,
нарушения конституции, архитектура, и чего нет как класса.

## 1. Главный диагноз

### Тезис 1. Конституция опережает реализацию

`DESIGN.md` описывает кит, которого в `src/` пока нет. Это не придирка к стилю —
это измеримо. Документ запрещает захардкоженные цвета — в `components.css` их два
(`stroke='white'` в чекбоксе, `white` в радио). Запрещает размытия — они в
`index.html`. Требует, чтобы новое значение становилось токеном — в компонентах
15 магических констант. Требует «проверьте в трёх плотностях» — плотность
сломана и не работает вообще. Требует, чтобы стили приложения выигрывали без
`!important` — в базе есть `!important`, который приложению не перебить.

Разрыв между документом и кодом — сам по себе главный риск: пока он есть,
`DESIGN.md` читается как обещание, а не как описание.

### Тезис 2. Светлая тема слабее тёмной, и это редкий случай

Обычно бывает наоборот. Здесь тёмная тема авторская и откалибрована: почти всё
проходит AA. Светлая — инверсия по инерции, и в ней проваливается вторичный
текст (3.79), placeholder и таймстемпы лога (2.57), жёлтый бейдж (3.02), жёлтая
точка статуса (1.92). Численно светлая тема — это черновик тёмной.

### Тезис 3. Это отличный tool-UI кит и пока очень слабый agentic-UI кит

Название обещает интерфейсы для агентов. Из агентного здесь — строка задачи и
лог. Нет ни одного примитива, вокруг которого строится реальный агентный
интерфейс: блок вызова инструмента, диф, запрос подтверждения у человека,
свёртка длинного вывода, стоимость/бюджет, ветвление и повтор. При этом
инспектор, дерево и num-field — сделаны, а они как раз про gamedev-тулинг, а не
про агентов. Кит честнее было бы назвать `tool-ui`, либо достроить агентный слой
— см. раздел 7. Это самый важный стратегический пункт всего разбора.

## 2. P0 — подтверждённые баги

Все пять воспроизведены замером, не рассуждением.

### 2.1 Плотность не работает для строк — `tokens.css:317`

```css
[data-density="compact"]    { --row-pad-y: var(--space-2); }   /* строка 307 */
[data-density="comfortable"]{ --row-pad-y: var(--space-5); }   /* строка 314 */
:root { --row-pad-y: var(--space-3); }                          /* строка 317 */
```

`:root` и `[data-density="…"]` имеют **одинаковую специфичность** (0,1,0), оба
матчат `<html>`, и дефолт объявлен последним — значит, он всегда выигрывает.

Замер: `--row-pad-y` = `6px` во всех трёх режимах, при том что `--control-h-md`
корректно меняется на `26px`. То есть плотность меняет высоту контролов, но не
трогает вертикальный ритм таблиц и списков — а это ровно то, ради чего плотность
и нужна.

**Решение.** Дефолты — всегда в `:where()`, чтобы специфичность была нулевой:

```css
:where(:root) { --row-pad-y: var(--space-3); }
```

И перенести дефолт вверх, в основной блок токенов, а не в хвост файла.

### 2.2 Системная тёмная тема получает светлые тени — `tokens.css:256`

Блок `@media (prefers-color-scheme: dark)` дублирует `[data-theme="dark"]`, и они
**уже разошлись**: медиазапрос не переопределяет `--shadow-popover` и
`--shadow-modal`.

Замер при системной тёмной теме без атрибута:

```
--shadow-popover → oklch(0 0 0 / 0.10)   ← светлая версия
[data-theme=dark] → oklch(0 0 0 / 0.45)   ← правильная
```

Поповер у пользователя с системной тёмной темой будет без тени вообще: тень
0.10 на поверхности 0.155 невидима. А тень — единственное, чем поповер отличается
от панели, потому что кит запрещает тени всем остальным.

Это ровно тот класс ошибки, о котором предупреждает сам `DESIGN.md`: «Дубликат —
это будущее расхождение». Дубликат разошёлся за один коммит.

**Решение — убрать дубликат конструктивно, а не синхронизировать руками.**
`light-dark()` (Baseline 2024, тот же уровень поддержки, что уже используемые
`oklch`, `@layer`, `:has()`) даёт одно объявление на токен:

```css
:root {
  color-scheme: light dark;

  --surface-page: light-dark(var(--n-1),  var(--n-13));
  --text-primary: light-dark(var(--n-12), var(--n-1));
  --text-muted:   light-dark(var(--n-8),  var(--n-6));

  /* light-dark() принимает только <color>, поэтому через неё проходит
     ЦВЕТ тени, а не значение целиком. */
  --shadow-color-far: light-dark(oklch(0 0 0 / 0.10), oklch(0 0 0 / 0.45));
  --shadow-popover: 0 4px 12px -2px var(--shadow-color-far);
}

[data-theme="light"] { color-scheme: light; }
[data-theme="dark"]  { color-scheme: dark;  }
```

Три блока схлопываются в один, расхождение становится невозможным по
конструкции, а переключение темы атрибутом продолжает работать, потому что
`light-dark()` читает именно `color-scheme`.

### 2.3 Колонки лога не выравниваются — `components.css:714`

`grid-template-columns` объявлен на `.log-line`, то есть **каждая строка — своя
отдельная сетка**. Ширина колонки уровня определяется длиной слова в этой
строке.

Замер по демо: сообщение начинается на `x = 128` у строк `info`/`warn` и на
`x = 135` у строки `error`. Семь пикселей рассинхрона, видно невооружённым
глазом на скриншоте.

Для кита, который построен на швейцарской сетке, разъезжающаяся колонка в самом
частом компоненте — это провал в главном.

**Решение.** Ширина по `ch`, а не по контенту:

```css
.log > .log-line > .log-time  { inline-size: 8ch; }
.log > .log-line > .log-level { inline-size: 5ch; }  /* trace|debug|info|warn|error */
```

Альтернатива — одна сетка на весь лог с `.log-line { display: contents }`, но
тогда теряется подсветка строки целиком и hover по строке. Для лога, где строку
надо уметь выделить и скопировать, `ch` правильнее.

### 2.4 Поле ввода неотличимо от панели — `components.css:133`

Замер фонов: `.input`, `.panel`, `.card` — все `oklch(0.994 0.002 75)`. Один и
тот же `--surface-raised`.

Значит, единственная граница поля — рамка `--border` с контрастом **1.31:1**
против требуемых 3:1 (WCAG 1.4.11). Поле на панели физически не видно, пока в
него не ткнёшь.

Причина архитектурная: в стопке `sunken < page < raised < overlay` нет слота для
«углубление под ввод». Она описывает вертикаль всплытия, но не описывает врез.

**Решение.** Отдельный семантический токен, а не переиспользование `raised`:

```css
:root {
  --surface-field: light-dark(var(--n-0), var(--n-13));
  --border-field:  light-dark(oklch(0 0 0 / 0.30), oklch(1 0 0 / 0.26));
}
.input, .textarea, .select, .num-field { background: var(--surface-field); border-color: var(--border-field); }
```

В тёмной теме поле становится **темнее** панели — это врез, как в Blender,
Unity и Figma, и для инструментального интерфейса это правильнее, чем всплытие.
Заодно рамка перестаёт быть несущей, и её можно оставить тихой.

### 2.5 Группа кнопок даёт двойную линию

`.btn-group > .btn { margin-inline-start: calc(var(--hairline) * -1) }` — сдвиг
ровно `-0.5px`. Но браузер **никогда не рисует border тоньше одного физического
пикселя**: замер при DPR 1.5 показал painted `0.666667px` при сдвиге `-0.5px`.
Остаток `0.167px` — это видимое утолщение шва. При DPR 1.0 (обычный внешний
монитор на Windows) painted будет `1px` при сдвиге `0.5px` — полпикселя двойной
рамки на каждом стыке.

Здесь же более общая проблема: `--hairline: 0.5px` на 1x-дисплее рендерится
идентично `--stroke: 1px`. То есть весь приём, вокруг которого построен раздел
«Приёмы» в `DESIGN.md`, на целевой платформе (Windows, часто 100% масштаб)
не даёт ничего.

**Решение.** Во-первых, хайрлайн по плотности пикселей:

```css
:root { --hairline: 1px; }
@media (min-resolution: 1.5dppx) { :root { --hairline: 0.5px; } }
```

Во-вторых, шов группы — не отрицательным полем, а фоном контейнера, который
просвечивает в зазоре. Работает при любом DPR:

```css
.btn-group {
  display: inline-flex;
  gap: var(--hairline);
  background: var(--border-strong);
  border-radius: var(--radius-md);
}
.btn-group > .btn { border: none; border-radius: 0; }
```

## 3. P0 — контраст и доступность

### 3.1 Провалы контраста

Посчитано из `tokens.css`. Порог AA: 4.5 для текста < 18px, 3.0 для нетекстовых
границ и индикаторов состояния (WCAG 1.4.3 / 1.4.11).

|---|---|---:|---:|---|

| `--text-faint` на sunken | таймстемпы в логе | **2.31** | 4.5 | ✗ |
| `--text-muted` на raised | `th`, `.kv dt`, `.prop-label`, `.task-meta` | **3.79** | 4.5 | ✗ |

Всё остальное проходит. Тёмная тема, кроме двух строк, чистая.

### 3.2 Разбор и конкретные значения замены

**`--text-faint` — проблема не в числе, а в употреблении.** Токен задуман как
«тише, чем muted», и это законно для чисто декоративного. Но им покрашены
таймстемпы лога и placeholder — то, что читают. Двойной фикс:

```css
--text-faint: light-dark(var(--n-7), var(--n-7));   /* 3.79 / 4.90 */
```

и правило в `DESIGN.md`: **`--text-faint` не применяется к тексту, который
пользователь может захотеть прочитать.** Таймстемп лога — это данные, ему
положен `--text-muted`.

**`--text-muted` в светлой — сдвиг на один шаг рампы.** `--n-8` вместо `--n-7`
даёт 5.90 на raised и 5.31 на sunken. Шаг уже существует, новых значений
заводить не нужно.

**Жёлтый — здесь две разные ошибки.**

`--warn-solid: var(--warn-3)` — единственный статус, который берёт третий шаг;
`ok` и `err` берут четвёртый. Скорее всего кто-то осветлил жёлтый, чтобы он
«выглядел жёлтым», и выпал из паттерна. Возврат к `--warn-4` даёт ровно 3.00 на
sunken — впритык, но проходит.

Для текста нужен новый шаг: `--warn-5: oklch(0.520 0.135 85)` → 4.93 на
`--warn-bg`. Аналогично `--ok-5: oklch(0.500 0.120 150)` → 5.02.

Это, кстати, ответ на вопрос, почему рампы статусов у вас 1/3/4/6: шаг 5 не
заведён именно там, где он нужен для текста на тонированном фоне.

**Тёмная primary-кнопка при наведении — закономерность, а не частный случай.**
В светлой теме hover идёт `a-4 → a-5`, то есть **темнее**, прочь от белой
подписи: 4.58 → 7.28, контраст растёт. В тёмной скопировали ту же идею наоборот
— `a-4 → a-3`, светлее: 4.58 → **2.61**. Подпись при наведении становится
нечитаемой.

Общий закон, который стоит записать в конституцию: **заливка сплошной кнопки
при наведении обязана уходить от цвета подписи, а не к нему.** Для белой
подписи это значит «темнее» в обеих темах. Практически:

```css
[data-theme="dark"] { --accent-hover: var(--a-5); }  /* 7.28 */
```

Потолок для белой подписи — `L ≈ 0.56`; всё, что светлее, ломает 4.5.

**Границы контролов — не красить всё темнее.** Соблазн поднять
`--border-strong` до alpha 0.42 (даёт 3.03) сделает интерфейс тяжёлым и убьёт
эстетику хайрлайна. Правильно различать два случая:

- рамка **несущая** (чекбокс, радио, дорожка свитча, поле ввода — граница и есть
  контрол) → обязана быть ≥ 3:1;
- рамка **декоративная** (панель, карточка, разделитель — есть ещё и разница
  поверхностей) → 1.4.11 к ней не применяется, можно оставить как есть.

Отсюда третий токен, а не подъём общего:

```css
--border-control: light-dark(oklch(0 0 0 / 0.42), oklch(1 0 0 / 0.34)); /* 3.03 / 3.0 */
```

и `--track` для выключенного свитча — туда же. Сейчас выключенный свитч при
контрасте 1.25 практически не виден: пользователь не отличает «выключено» от
«элемента нет».

### 3.3 Клавиатура: списочные примитивы недоступны

Замер: `tabindex` есть у **0 из 6** элементов дерева и **0 из 6** строк задач.
Ни дерево, ни очередь агентов, ни строки таблицы нельзя ни сфокусировать, ни
выбрать с клавиатуры. Для инструмента, в котором сидят часами, это тяжелее, чем
любая проблема контраста.

Понятно, что roving tabindex — это JS и он уйдёт в Svelte-слой. Но кит должен
хотя бы:

- явно объявить это контрактом в `DESIGN.md` (сейчас в «что не сделано» этого нет);
- дать стиль `:focus-visible` для `[role="treeitem"]`, `[role="option"]`, `tr`;
- не притворяться доступным через ARIA, которая на самом деле невалидна — см. ниже.

### 3.4 ARIA невалидна ровно там, где на неё завязаны стили

Кит использует прекрасный приём: состояние живёт в ARIA-атрибуте, а CSS его
читает — одно состояние, один источник. Но работает это, только если роли
настоящие. Сейчас:

- `.segmented` в демо — `role="tablist"` / `role="tab"`, хотя это переключатель
  плотности, а не вкладки: нет ни `aria-controls`, ни `tabpanel`. Должно быть
  `role="radiogroup"` / `role="radio"` + `aria-checked`.
- `.task[aria-selected="true"]` — `<div>` без роли. `aria-selected` валиден
  только на `option`, `row`, `tab`, `gridcell`, `treeitem`.
- `.tree-item[aria-expanded]` / `[aria-selected]` — `<div>` без `role="treeitem"`
  и без контейнера `role="tree"`.
- 21 кнопка без `type="button"` — внутри `<form>` каждая отправит форму.
- 4 полосы прогресса, **0** с `role="progressbar"`: значение прогресса
  существует только как ширина в пикселях и недоступно ни скринридеру, ни тестам.

Последнее особенно обидно для кита, который отдельно гордится честностью
неопределённого прогресса: честность видна глазом, но не программно.

**Решение.** Зафиксировать в конституции разметочный контракт для каждого
списочного компонента и добавить его в живую спецификацию — сейчас демо учит
неправильному, а копировать будут именно из демо.

### 3.5 Reduced-motion выключает признак работы

`base.css:119` — бланкетное правило схлопывает `animation-duration` до `0.01ms`
и `animation-iteration-count` до `1` для **всего**. Комментарий утверждает, что
это «не выключение анимаций, а сжатие длительностей», и для `transition` это
верно. Для **бесконечных индикаторов активности это именно выключение**:
спиннер замирает в случайной фазе, `.dot--running` перестаёт пульсировать,
каретка стриминга застывает.

То есть при `prefers-reduced-motion: reduce` кит, вся работа которого —
показывать, что машина занята, **перестаёт показывать, что машина занята**.

Плюс `!important` внутри слоя `kit.base` перебивает неважные объявления
приложения вне слоёв — что прямо противоречит обещанию `DESIGN.md`: «стили
приложения лежат вне слоёв кита и всегда выигрывают без `!important`».

**Решение.** Разделить переходы и активность:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    transition-duration: 0.01ms;
    scroll-behavior: auto;
  }
  /* Индикаторы активности не выключаются, а замедляются: движение остаётся
     считываемым как «идёт», но перестаёт дёргать периферийное зрение. */
  .spinner { animation-duration: 2.4s; }
  .dot--running { animation-duration: 3s; }
  .caret { animation: none; opacity: 1; }
  .meter--indeterminate > .meter-fill { animation-duration: 3s; }
}
```

Без `!important`, чтобы обещание про слои осталось правдой.

### 3.6 Нет режима принудительных цветов

Целевая платформа — Windows. `@media (forced-colors: active)` (High Contrast)
не обработан вообще. В этом режиме все фоны и alpha-рамки сбрасываются на
системные, и весь кит, построенный на «хайрлайн + разница поверхностей»,
схлопывается в плоскость: панели, поля, карточки и выделение станут неразличимы.

Минимум:

```css
@media (forced-colors: active) {
  .panel, .card, .input, .btn, .num-field { border: 1px solid CanvasText; }
  .badge { border: 1px solid CanvasText; }
  .task[aria-selected="true"], .tree-item[aria-selected="true"] { forced-color-adjust: none; }
  .meter-fill { forced-color-adjust: none; background: Highlight; }
}
```

позиционированного как «спецификация в виде кода», это дороже обычного:

- `.select` (`:155`): «стрелка — токен, разрешённый на этапе авторства» — а в коде

- `.checkbox` (`:188`): «`accent-color` делает большую часть работы» —
  `accent-color` не используется нигде, стоит `appearance: none` и ручная отрисовка.
- `base.css:119`: «не выключение анимаций» — на бесконечных анимациях именно
  выключение (§3.5).

## 5. Архитектура токенов

### 5.1 Мёртвый слой

Не используются нигде: `--n-3`, `--n-4`, `--n-10`, `--a-2`, `--a-6`, `--ok-6`,
`--warn-6`, `--err-6`, `--text-inverse`, `--surface-overlay`, `--tracking-wide`,
`--space-0`, `--z-popover`, `--z-modal`, `--z-toast`.

Часть — законный задел (z-индексы под поповеры). Но `--text-inverse` дублирует
`--accent-on` по смыслу, а 5 неиспользуемых шагов из 14 в нейтральной рампе —
признак, что рампа спроектирована «на глаз с запасом», а не выведена из
потребностей семантики. Либо задокументировать шаги как зарезервированные, либо
сжать рампу до 10–11 шагов.

### 5.2 Литералы в семантическом слое

```css
--surface-page:     oklch(0.155 0.003 75);            /* 15-й шаг, которого нет в рампе */
--surface-selected: oklch(0.560 0.155 250 / 0.16);    /* повтор литерала --a-4 */
--accent-bg:        oklch(0.560 0.155 250 / 0.15);    /* тот же литерал ещё раз */
--ok-bg:            oklch(0.545 0.120 150 / 0.16);    /* литерал --ok-4 */
--warn-bg:          oklch(0.640 0.135 85 / 0.16);
--err-bg:           oklch(0.545 0.185 25 / 0.16);
```

Значение `--a-4` продублировано в тёмной теме четыре раза. Подкрутите акцент —
и фоны молча останутся на старом тоне. Это тот же баг, что §2.2, только ещё не
выстреливший.

**Решение** — `color-mix`, и связь становится явной:

```css
--surface-selected: color-mix(in oklab, var(--a-4) 16%, transparent);
--accent-bg:        color-mix(in oklab, var(--a-4) 15%, transparent);
--ok-bg:            color-mix(in oklab, var(--ok-4) 16%, transparent);
```

А `oklch(0.155 …)` — завести как `--n-12-5` в рампе, раз он всё равно нужен.

### 5.3 Плотность неполна и асимметрична

- `compact` задаёт `--control-pad-*`, `comfortable` — нет. Кнопка 44px с
  дефолтным паддингом выглядит сдавленной.
- Плотность не трогает **ни шкалу пространства, ни типографику**. Строка в
  `compact` — 22px, а паддинг панели вокруг неё остаётся 12px. Настоящая
  плотность требует семантического яруса отступов (`--pad-panel`, `--gap-row`),
  которого в ките нет: компоненты берут `--space-*` напрямую, поэтому
  переключить их разом невозможно.

**Решение.** Ввести узкий ярус «пространство по назначению» между шкалой и
компонентами — это единственное, что делает плотность управляемой:

```css
:where(:root) {
  --pad-panel:  var(--space-5);
  --pad-card:   var(--space-6);
  --gap-row:    var(--space-3);
  --gap-inline: var(--space-4);
}
[data-density="compact"]     { --pad-panel: var(--space-4); --gap-row: var(--space-2); }
[data-density="comfortable"] { --pad-panel: var(--space-6); --gap-row: var(--space-5); }
```

### 5.4 База типографики выбрана против собственного правила

`DESIGN.md` говорит: 13px — база интерфейса, 15px — проза. `base.css` ставит
`body { font-size: 15px; line-height: 1.65 }`, то есть базой сделал прозу.
Следствие: **каждый без исключения компонент вынужден переобъявлять
`font-size`** — проверьте, `font-size` встречается в `components.css` 27 раз. И
любой `<div>` приложения без класса наследует прозу вместо интерфейса.

**Решение** — инвертировать: база 13/1.4, проза опт-ин.

```css
body { font-size: var(--text-sm); line-height: var(--leading-ui); }
.prose { font-size: var(--text-md); line-height: var(--leading-prose); }
```

После этого из компонентов уходит ~20 объявлений `font-size`, и правило из
конституции наконец становится правдой в коде.

### 5.5 Акцент и «идёт» — один и тот же синий

`--badge--running` красится `--accent-bg`/`--accent-text`, `.dot--running` —
`--accent-solid`. То есть синий означает одновременно «нажми меня» и «выполняется».
На экране очереди с primary-кнопкой рядом это ровно тот случай, против которого
написан Закон 1: цвет кодирует две разные вещи.

Это не запрос второго акцента — это признание, что статусов на самом деле **пять**,
а не четыре: `queued`, `running`, `ok`, `warn`, `error`. Варианта два:

1. дать `running` собственный зарезервированный тон (например, циан 220) и
   вывести его из акцентной рампы;
2. оставить `running` нейтральным и возложить всю передачу состояния на
   пульсирующую точку и слово — акцент тогда чист и означает только интеракцию.

Второе строже и лучше соответствует духу документа.

### 5.6 Четыре конкурирующих способа кодировать состояние

В одном файле сосуществуют: `.badge--ok` (BEM-модификатор), `.is-done`
(состояние классом), `[aria-selected]` (ARIA), `[data-density]` (data-атрибут).
Плюс `.meter--indeterminate` — это состояние, оформленное как вариант.

**Решение** — одно правило, записанное в конституцию: **вариант (то, что решает
автор разметки) — модификатор `--`; состояние (то, что меняется во время жизни)
— ARIA, если роль позволяет, иначе `data-state`.** Тогда:

```html
<div class="task" role="option" aria-selected="true" data-state="running">
<div class="meter" role="progressbar" data-state="indeterminate">
```

CSS читает одно место, и Svelte-слой не изобретает второй источник истины.

## 6. API компонентов

Собрано по убыванию цены ошибки.

**`.metric-delta.is-up` / `.is-down` названы направлением, а красят полярность.**
В демо `is-up` стоит на «↓ 18%» (время упало — это хорошо), `is-down` — на
«↑ 5 новых» (предупреждений прибавилось — плохо). Классы читаются как стрелка, а
означают оценку. Это гарантированная ошибка применения в первый же месяц.
Переименовать в `data-polarity="good | bad | neutral"` и включить стрелку в
API компонента, а не в контент.

**`.kv` и `.prop` — два почти одинаковых примитива, разошедшиеся случайно.**
Замер: колонка 80px против 92px, тип `--text-sm` против `--text-xs`, цвет
`--text-muted` против `--text-secondary`. Различие в задаче законно (чтение
против редактирования), различие в метрике — нет. Общий токен `--label-col` и
общая типографика.

**`.panel-body--flush` не покрывает свой же случай.** В демо после него дважды
идёт `style="padding: var(--space-3)"` — то есть булев модификатор не выражает
«список с малым отступом». Заменить на переменную `--panel-body-pad`.

**`.panel { overflow: hidden }` обрежет будущие поповеры.** Поповер, открытый
внутри панели, будет срезан по её радиусу. Это конфликт, заложенный до того, как
поповеры написаны. Решать через top-layer (`popover` / портал) и записать это
контрактом сейчас, а не когда обнаружится.

**Дочерние комбинаторы слишком жёсткие.** `.log > .log-line`, `.meter >
.meter-fill`, `.panel-header > .panel-title`. В Svelte обёртки появляются
постоянно (`{#each}`, transition-обёртки, `<svelte:fragment>` не всегда спасает),
и стиль молча отвалится. Либо потомковый комбинатор, либо явный контракт «между
X и Y не должно быть узлов» в документации.

**Глобальные `@keyframes`: `pulse`, `spin`, `blink`, `sweep`.** Слои не изолируют
keyframes. Это четыре самых частых имени анимаций на свете; коллизия с
приложением или сторонней библиотекой — вопрос времени. Префикс `au-`.

**Имена классов без пространства имён.** `.card`, `.table`, `.input`, `.panel`,
`.badge`, `.note`, `.log`, `.code`, `.field`, `.empty`, `.dot`. Кит
подключается одной строкой в произвольное приложение; `@layer` защищает от войны
специфичности, но **не защищает от совпадения имён** — `.card` приложения вне
слоёв выиграет всегда и молча. Для кита, который планируют переиспользовать,
это дефект дистрибуции. Либо префикс, либо явное предупреждение в README.

**Прочее, коротко:**

- `.select` — стрелка из двух `linear-gradient` даёт сплошной треугольник, а не
  шеврон, и позиционируется физическими `calc(100% - 15px)`: в RTL уедет, хотя
  весь остальной кит на логических свойствах. То же с `translate: 12px 0` у
  `.switch::after`. Решение — обёртка `.select-wrap` с `::after` из двух границ,
  повёрнутых на 45°, на `currentColor` и логических отступах.
- `.u-mono { font-size: 0.925em }` поверх правила `code { font-size: 0.925em }`
  даёт `0.855em` у `<code class="u-mono">`. И `<pre class="code"><code>` даёт
  11.1px — на грани объявленного пола в 11px.
- `.num-field > input` не имеет доступного имени: скринридер прочитает «spin
  button, 128» без указания оси. `.num-axis` — не `<label>`.
- `.prop-label` обрезается многоточием без `title` — прочитать полное имя
  свойства невозможно.
- `.task:hover` и `.task[aria-selected]` объявлены с одинаковой специфичностью,
  выделение объявлено позже — значит, у выделенной строки **нет ховера**.
  В светлой теме `--surface-selected` непрозрачный, в тёмной — alpha; из-за
  этого поведение при наложении состояний в темах разное. Сделать alpha в обеих.
- `.tree-item[aria-selected]` меняет цвет текста на акцентный, `.task[aria-selected]`
  — нет. Два списочных примитива говорят о выделении на разных языках.
- Таблица: нет `position: sticky` у `thead` (обязателен для инструментальной
  таблицы), нет стиля выделенной строки, нет `:focus-within`, нет конвенции
  пустой ячейки. Строка задачи выделяется, строка таблицы — нет.
- `.panel-header` и `.toolbar` оба несут `border-bottom` — в инспекторе видны две
  линии подряд. Нужно правило склейки: `.panel-header + .toolbar { border-top: none }`.
- Нет `scrollbar-gutter: stable` у `.panel-body` и `.log` — контент прыгает на
  ширину скроллбара, когда лог перерастает высоту. Для растущего лога это
  постоянное дёрганье.
- Нет `overscroll-behavior: contain` — прокрутка панели уходит в страницу.
- `.spinner` рисует кольцо цветом `--track` (1.25:1) — на `--surface-sunken`
  кольца практически нет, виден только вращающийся сегмент.
- `.field` даёт одинаковый зазор 6px между подписью и полем и между полем и
  подсказкой. По Гештальту подсказка принадлежит полю теснее, чем подпись —
  зазоры должны различаться.
- `:focus-visible { border-radius: var(--radius-sm) }` в `base.css:88` меняет
  радиус **самого элемента**, а не обводки. Компоненты со своим радиусом это
  перекрывают (слой `kit.components` позже), но для всего остального это мина, и
  сама строка не нужна: современная обводка и так следует радиусу элемента.
- `text-rendering: optimizeLegibility` — известный источник проблем с
  производительностью и кернингом; вместе с `-webkit-font-smoothing: antialiased`,
  который истончает текст на macOS, это работает **против** и без того
  проблемного контраста вторичного текста. Обе строки стоит убрать.
- `word-break: break-word` в `.log` — устаревшее; правильно `overflow-wrap: anywhere`.
- `@import` × 3 в `kit.css` — четыре последовательных запроса вместо одного.
  Для «без сборки» приемлемо, но рядом стоит класть склеенный `kit.css`.

## 7. Чего нет как класса: агентный слой

Это самый важный раздел. Всё выше — исправимые дефекты; здесь — недостающая
половина продукта.

Кит объявляет своей областью «очереди задач, прогоны, логи, инспекторы,
состояния и неопределённость». Из шести пунктов закрыты четыре, и закрыты
хорошо. Но реальный агентный интерфейс состоит не из них. Отсутствуют:

**Запрос подтверждения у человека.** Определяющее взаимодействие агентных систем:
агент останавливается и спрашивает разрешения на действие. Нужен встроенный в
поток блок с описанием действия, его последствий, кнопками «разрешить / отклонить
/ разрешить всегда» и состоянием ожидания. Ни одного примитива под это нет.
Это пробел №1.

**Блок вызова инструмента.** Свёрнутая строка «прочитал 4 файла», раскрывающаяся
в аргументы и результат; состояния «выполняется / успех / ошибка / отменён».
`.task` — это строка очереди, а не раскрываемый шаг с телом.

**Диф.** Агенты производят изменения кода. Без просмотра дифа с построчной
разметкой (`+`/`−`, контекст, свёртка неизменённых участков) кит не покрывает
основной артефакт работы агента.

**Свёртка длинного вывода.** «Показано 200 из 4 812 строк, развернуть». Лог без
этого — либо обрезан молча, либо кладёт страницу.

**Стоимость и бюджет.** В демо токены показаны трижды и каждый раз вручную. Это
первоклассная сущность агентного UI (токены, деньги, лимит, прогноз до
исчерпания), а не число в ячейке.

**Скелетон / плейсхолдер загрузки.** Кит про ожидание — и не имеет примитива
ожидания содержимого.

**Блок ошибки с восстановлением.** Заголовок, причина, что было предпринято,
кнопка повтора. Сейчас есть `.note--error` — полоска и текст, без действий.

**Тело сообщения / стриминг.** Есть `.caret`, но нет стилей самого потока: абзацы,
списки, инлайн-код внутри ответа агента, и правило «не дёргать layout, пока текст
дописывается».

**Таймлайн параллельных агентов.** Документ упоминает параллельные прогоны,
компонента под них нет.

**Мелочи с большой отдачей:** копирование блока кода/лога одной кнопкой,
фильтр-поиск по логу с очисткой, отображение горячих клавиш (`<kbd>` есть в
сбросе, но не стилизован — а инструмент живёт на клавиатуре), хлебные крошки по
прогонам.

**Иконок нет как системы.** В демо — текстовые глифы `⟳ ↔ ⟲ ⤢ ▶`, у которых
разные метрики в разных шрифтах и риск подстановки эмодзи. Для инструментального
интерфейса это заметный пробел: нужен токен размера, правило (inline SVG,
`stroke: currentColor`, толщина 1.25, сетка 16) и минимальный набор из ~20 знаков.

## 8. Живая спецификация как продукт

`index.html` заявлен как «демо и документация одновременно». Как документация он
хорош — тексты `.why` объясняют *почему*, а не *что*, это редкость. Как источник
для копирования он сломан: **в разметке ~20 инлайновых `style`**.

```html
<div style="font-weight:500;font-size:var(--text-sm)">worldgen-01</div>
<div style="font-size:var(--text-xs);color:var(--text-muted);margin-top:2px">…</div>
<select class="select" style="height:var(--control-h-sm);font-size:var(--text-xs)">
```

Каждый такой `style` — это отсутствующий компонент или утилита, обнаруженная и
залатанная на месте. Полезно принять правило: **демо не имеет права на инлайновый
стиль; если он понадобился — кит неполон.** Тогда живая спецификация начинает
работать как тест покрытия, а не как витрина. Три примера выше — это
недостающие `.card-title`/`.card-sub` и размерный вариант селекта.

Остальное по демо:

- Переключатель темы не сохраняется в `localStorage`, не выставляет
  `aria-pressed` и подписан «Тема» — не сообщает ни текущего состояния, ни того,
  что произойдёт.
- Переключатель плотности — невалидный `role="tab"` (§3.4).
- Нет `<main>`, нет ориентиров, нет skip-link.
- `lang="ru"`, но `dir` не обрабатывается, а два компонента используют физические
  координаты (§6) — RTL сломается.
- Единицы измерения набраны непоследовательно: `42<span>с</span>` без пробела,
  рядом «2,1 с» и «18,2 с» с пробелом. В ките, который отдельно оговаривает, как
  подавать единицу, это заметно. Нужна конвенция форматирования (неразрывный
  пробел перед единицей) и, лучше, компонент/утилита под неё.

## 9. Идеальное решение — целевая архитектура

Не список заплаток, а то, к чему стоит прийти.

### 9.1 Токены — четыре яруса вместо двух

Сейчас: рампы → семантика. Между ними и компонентами не хватает двух ярусов,
и именно их отсутствие порождает 15 магических констант и сломанную плотность.

```
1. Рампы          сырые шаги, не меняются между темами
2. Семантика      для чего цвет нужен       ← light-dark(), одно объявление
3. Роли           --pad-panel, --gap-row, --border-control, --surface-field,
                  --size-dot, --size-check, --size-gutter, --label-col
                  ← единственный ярус, который перенастраивает плотность
4. Компонент      --btn-bg, --btn-fg — 2–3 переменные, как и требует документ
```

Ярус 3 — это то, чего не хватает больше всего: он превращает плотность из
переключателя высот в настоящий регулятор, и он же убивает магические числа,
потому что каждому даёт имя.

### 9.2 Темы — одно объявление на токен

`color-scheme: light dark` + `light-dark()` (§2.2). Три блока → один. Расхождение
становится невозможным, а не «маловероятным».

### 9.3 Состояние — один язык

Вариант — модификатор `--`. Состояние — ARIA при валидной роли, иначе
`data-state`. Разметочный контракт каждого списочного компонента (роль,
атрибуты, что обязано быть в DOM) записан в конституцию и продемонстрирован
в живой спецификации.

### 9.4 Доступность как ограничение, а не как проверка

Три правила, встроенные в процесс:

1. Ни один семантический токен не попадает в кит, пока не посчитана его пара с
   каждой поверхностью, на которой он может оказаться. Скрипт из этой ревизии
   стоит положить в репозиторий и гонять как тест — 40 строк, ноль зависимостей.
2. Несущая рамка — ≥ 3:1, декоративная — свободна. Это два разных токена
   (`--border-control` / `--border`), а не один.
3. `prefers-reduced-motion` замедляет индикаторы активности, но не гасит их;
   `forced-colors` обработан.

### 9.5 Агентный слой достроен до паритета с инструментальным

По приоритету: запрос подтверждения → блок вызова инструмента → диф → свёртка
вывода → бюджет/стоимость → скелетон → блок ошибки с повтором. Первые три
покрывают, наверное, 80% экранного времени реального агентного интерфейса.

### 9.6 Живая спецификация — тест покрытия

Ноль инлайновых стилей. Каждый блок демо — валидная разметка, которую можно
скопировать целиком. Раздел «антипримеры» (как **не** надо: четыре цвета на
четырёх полосках, заголовок капсом, тень на карточке) — документ уже написан в
этой полемической интонации, и показанный рядом антипример работает сильнее
любого абзаца.

### 9.7 Дистрибуция

Префикс классов или явное предупреждение. Префикс `au-` у keyframes. Склеенный
`kit.css` рядом с модульными. `package.json`, версия, заявленный минимум
браузеров (сейчас фактически Chrome 123+ / Safari 17.5+ из-за `oklch`, `@layer`,
вложенности, `:has()`, а с `light-dark()` — то же самое).

## 10. Порядок работ

**Сначала — то, что чинится за час и снимает большую часть ущерба:**

1. `:where(:root)` для дефолта `--row-pad-y` — плотность оживает (§2.1).
2. Ширины `ch` в логе — колонки перестают разъезжаться (§2.3).
3. `--warn-solid: var(--warn-4)` — жёлтая точка становится видимой (§3.2).
4. Тёмная `--accent-hover: var(--a-5)` — подпись primary перестаёт исчезать (§3.2).
5. `--text-muted: var(--n-8)`, `--text-faint: var(--n-7)` в светлой (§3.2).
6. `--hairline` по `min-resolution` (§2.5).

**Затем — структурное, в этом порядке:**

7. Темы на `light-dark()`, литералы на `color-mix` (§2.2, §5.2).
8. `--surface-field` + `--border-control` — поля и чекбоксы становятся видимыми
   и проходят 1.4.11 (§2.4, §3.2).
9. База типографики 13/1.4, проза опт-ин — минус ~20 объявлений в компонентах (§5.4).
10. Ярус ролей, магические числа получают имена, плотность становится настоящей (§5.3, §9.1).
11. Один язык состояний, валидные роли, `role="progressbar"` (§3.4, §5.6).
12. `reduced-motion` без `!important`, `forced-colors` (§3.5, §3.6).

**Параллельно — то, что определяет ценность кита:**

13. Агентный слой (§7), начиная с запроса подтверждения.
14. Иконки как система.
15. Живая спецификация без инлайновых стилей + скрипт контраста в CI.

## Приложение. Что стоит дописать в конституцию

Правила, выведенные из найденного здесь. Каждое защищает от конкретной ошибки,
которая уже произошла:

- **Заливка сплошной кнопки при наведении уходит от цвета подписи, а не к нему.**
  В тёмной теме это значит «темнее», а не «светлее». (Иначе — §3.2.)
- **`--text-faint` не применяется к тексту, который читают.** Таймстемп лога —
  данные, а не декорация.
- **Несущая рамка и декоративная рамка — разные токены.** Если граница и есть
  контрол, у неё 3:1.
- **Reduced-motion замедляет индикаторы активности, но не гасит их.** Кит про
  ожидание обязан показывать ожидание всегда.
- **Дефолты объявляются через `:where()`.** Дефолт с той же специфичностью, что
  и переопределение, — это переопределение, объявленное позже.
- **Демо не имеет права на инлайновый стиль.** Инлайновый стиль в спецификации
  означает дыру в ките.
- **Один и тот же тон не может означать «интеракция» и «состояние».**
- **Комментарий, разошедшийся с кодом, — такой же баг, как расхождение токенов.**
  Здесь их три.
