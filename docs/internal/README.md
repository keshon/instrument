# Внутренние документы

Здесь лежат **процессные артефакты**, а не документация. Они описывают
состояние кита на момент своего написания и намеренно не обновляются: это
история решений, и переписывать её задним числом значит потерять её.

| Документ | Что это | Статус |
|---|---|---|
| [REVIEW.md](REVIEW.md) | ревизия CSS от 2026-08-05: контраст, токены, API, доступность | **отработал** — требования выполнены волнами 1–4 |
| [SCOPE.md](SCOPE.md) | план покрытия дашбордов и админок, четыре волны | **выполнен** |
| [PAGE-CONTRACT.md](PAGE-CONTRACT.md) | канонический контракт страницы компонента: словарь разделов, порядок, обязательное | **живой** — обновляется вместе со словарём в `site/internal/content/sections.go` |
| [DOCS-SHAPE.md](DOCS-SHAPE.md) | решение о форме страницы справочника: матрица вместо выбранных примеров, проза в foundations | **план** — до того, как check.Contract начнёт сторожить новый словарь |
| [DECISIONS.md](DECISIONS.md) | обоснования и замеры, вынесенные из пользовательской документации: почему правило именно такое | **пополняется** — по записи на решение |

**Имена классов в `REVIEW.md` и `SCOPE.md` оставлены без префикса `inst-`.**
Оба документа описывают состояние библиотеки до этапа 0 роадмапа, когда классы
действительно назывались `.btn` и `.tag`; разбор столкновения имён в `SCOPE.md`
держится именно на этом.
