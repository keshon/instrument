Нативный `input[type=range]`, приведённый к метрике кита. Значение выбирают
положением на шкале: слайдер отвечает на «побольше или поменьше», а не на
«сколько именно».

```html preview
<input class="inst-slider" type="range" min="0" max="16" value="6" step="1" style="--fill:37.5%"
       id="agents" aria-label="Параллельных агентов">
```

## Использование

```html
<input class="inst-slider" type="range" min="0" max="100" value="72" style="--fill:72%"
       aria-label="Плотность растительности">
```

| Что | Обязательно | Почему |
|---|---|---|
| `type="range"` | да | Всё поведение — от платформы: клавиатура, шаг, объявление значения. Класс оформляет нативные псевдоэлементы и на другом типе не делает ничего |
| `min` и `max` | да | Без границ шкала неинтерпретируема, а `aria-valuemin/max` платформа выведет из них сама |
| `<label for>` или `aria-label` | да | У слайдера нет собственного текста |
| `step` | нет | Умолчание — `1`. Ставьте явно, когда шаг не единица |
| `style="--fill: 45%"` | нет | Заливка дорожки до бегунка. Со скриптом считается сама; без скрипта объявите долю в разметке, иначе дорожка нарисуется пустой при непустом значении. Это **канал данных**, а не оформление — как `inline-size` у [меры](../charts/meter.md) |
| `<output for>` для числа | нет | Семантическая связь вместо подписи, меняющейся на каждом шаге |

Слайдер тянется на **100% ширины контейнера**. В ряду с другими элементами
дайте ему явный `flex` и `min-inline-size: 0`, иначе он вытолкнет соседа на
следующую строку.

## Когда использовать

| Используйте | Возьмите другое |
|---|---|
| Приблизительное значение из непрерывного диапазона: громкость, плотность, порог | **Точное число, которое вводят цифрами** — [числовое поле](./num-field.md) или [текстовое поле](./input.md): попасть бегунком в 47 из 100 нельзя |
| Диапазон, у которого видно оба конца и текущее положение | **Значение без известных границ** — [текстовое поле](./input.md): у слайдера обязаны быть `min` и `max` |
| Настройка, которую крутят и сразу видят результат | **Включение и выключение** — свитч в [переключателях](./toggles.md) |
| Строка свойства в инспекторе | **Показ величины без ввода** — [мера](../charts/meter.md): слайдер выглядит как контрол и приглашает его тянуть |

## Устройство

**Дорожка заполнена до бегунка.** Без заливки слайдер сообщает только «здесь
есть слайдер»: положение точки на ровной полосе приходится оценивать
глазомером, тогда как доля читается формой. Пустая часть берёт `--track` плюс
внутренний хайрлайн, заполненная — `--accent-mark`.

Бегунок несёт **кольцо цвета поверхности** и потому остаётся различимым там,
где наезжает на заполненную часть собственной дорожки.

| Часть | Токен размера | Замечание |
|---|---|---|
| Дорожка | `--size-track`, 4px | `--track` плюс хайрлайн `--border` |
| Бегунок | `--size-thumb`, 14px | В плотности `compact` — 12px, в `comfortable` — 16px |
| Общая высота | `--size-icon`, 16px | Чтобы слайдер вставал в строку свойства по той же метрике, что значок |

Нажатие увеличивает бегунок до `1.15` — отклик надо почувствовать, а не
разглядывать.

Заливка сделана **двумя сплошными зонами с общей границей**, а не
проприетарным `::-moz-range-progress` — у него нет аналога в Chromium, и
дорожка заполнялась бы в одном браузере из двух. Остановки совпадают, перехода
между цветами нет, поэтому запрет кита на градиенты это не нарушает: тот же
приём, что у заливки [спарклайна](../charts/sparkline.md).

Долю держит `--fill`. CSS не умеет прочитать `value` у `input`, поэтому её
считает [kit.js](#js) — но **начальное значение объявляет разметка**, и без
скрипта дорожка показывает то, с чем страница пришла, а не ноль.

## Поведение

### Вывод значения

:::note
**Число рядом с бегунком держит [kit.js](#js).** Связать положение с текстом
средствами CSS нельзя, поэтому это делает модуль: объявите `<output for>` —
дальше он сам.

Без модуля слайдер **полностью работает**: значение уходит с формой, скринридер
объявляет его на каждом шаге. Не обновляется только видимое число.
:::

```html preview
<div class="inst-cluster">
  <input class="inst-slider" type="range" min="0" max="16" value="6" step="1" style="--fill:37.5%"
         id="sl" aria-label="Параллельных агентов">
  <output for="sl">6</output>
</div>
```

Пример живой: потяните бегунок — число меняет кит.

`<output for>` связывает число со слайдером семантически, поэтому дублировать
его в `aria-label` не нужно — и не следует: подпись, меняющаяся на каждом
шаге, превращает объявление в шум.

## JS

Подключите модуль один раз на страницу — инициализировать компоненты по
отдельности не нужно, кит работает делегированием и видит узлы, пришедшие
позже.

```html
<script type="module" src="src/kit.js"></script>
```

### Что делает кит

Пример в разделе «Вывод значения» живой: потяните бегунок, число рядом меняет кит.

Держит в `<output for>` текущее значение бегунка — при вводе и при загрузке
страницы. Связь уже объявлена атрибутом `for`; синхронизировать её вручную
значило бы писать одну и ту же строку в каждом приложении.

Без модуля слайдер **полностью работает**: значение уходит с формой,
скринридер объявляет его на каждом шаге. Не обновляется только видимое число.

### События

Своих нет — читайте нативный `input`.

```js
sl.addEventListener('input', (e) => preview.setAgents(+e.target.value));
```

### Методы

`refresh(root)` проставляет числа заново. Нужно, если разметка пришла в обход
наблюдателя — например, в тесте.

## Правила

:::do Слайдер для приблизительного
«Побольше или поменьше» — единственный вопрос, на который он отвечает быстрее
поля.
:::

:::dont Слайдер для точного числа
Попасть бегунком в 47 из 100 зависит от моторики. Там, где число задают точно,
нужна пара «слайдер плюс [поле](./num-field.md)».
:::

:::do Число через output
`<output for>` связан со слайдером семантически и не мешает объявлению
значения.
:::

:::dont Значение в aria-label
Подпись, меняющаяся на каждом шаге, превращает объявление в шум.
:::

## Доступность

| | |
|---|---|
| Клавиатура | Стрелки — шаг, `PageUp` и `PageDown` — крупный шаг, `Home` и `End` — концы диапазона. Всё нативное, кит ничего не перехватывает |
| Роль и значение | `slider` с `aria-valuenow` — от платформы. Руками ставить не нужно, а `aria-valuetext` пригодится, когда число само по себе непонятно: «6 агентов» вместо «6» |
| Имя | `<label for>` или `aria-label`. Число выводится через `<output>`, а не подмешивается в имя |
| Фокус | Нативное кольцо. Оно рисуется вокруг контрола целиком — бегунок 14px кольца не удержал бы |
| Контраст | Бегунок держит 3:1 против поверхности **и** против дорожки: кольцо цвета поверхности разделяет их там, где они накладываются |
| Цель нажатия | Бегунок 14px — **ниже 24px по WCAG 2.5.8**, но нажатие принимает дорожка по всей высоте `--size-icon`, а положение достижимо с клавиатуры. Там, где слайдер единственный способ задать значение, дайте рядом [числовое поле](./num-field.md) |
| Точность | Слайдер не годится для значений, которые надо задать точно: попадание в конкретное число зависит от моторики. Пара «слайдер плюс поле» решает это |
| Уменьшенное движение | Увеличение бегунка при нажатии — переход, а не бесконечная анимация: схлопывается вместе со всеми переходами |
