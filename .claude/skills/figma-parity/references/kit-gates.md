# Что тянет за собой правка

Кит держит несколько сцепленных гарантий, и почти любое изменение задевает
больше одного файла. Список ниже — не бюрократия, а перечень мест, где сборка
или проверка упадёт, если забыть.

## Меняете значение существующего токена

- Перепишите комментарий, который защищал старое значение. Комментарии кита —
  проектный журнал; устаревшее «почему» вреднее отсутствующего.
- `cmd/contrast` проверит пары во всех 6 темах × 4 акцентах.
- Если токен назван на странице компонента в блоке `api:` — проверьте, что имя
  ещё верное.

## Заводите новый токен

- Место — `src/tokens.css`, рядом с роднёй по смыслу.
- Запишите его в таблицу в `docs/foundations/tokens.md`: там колонки «Светлая» и
  «Тёмная», и рядом абзац с обоснованием, если токен вводит новое понятие.
- Проверьте поведение в **светлых** темах отдельно. Прозрачный чёрный на белом
  набирает светлоту быстрее, чем на тёмном: одинаковая альфа даёт в светлой
  теме кирпич. У `--surface-recessed` шаг в светлых вчетверо мельче.

## Заводите новый класс

- `cmd/docscheck` держит стопроцентное покрытие: класс без страницы роняет
  проверку.
- Страница компонента обязана иметь разделы из словаря: **Использование ·
  Когда использовать · Состояния · JS** (если объявлен `js:`) **· Доступность ·
  API · Связанное**. Свой заголовок вне словаря — только как `###` внутри
  канонического раздела.
- В шапке нужен блок `api:` со списком классов, атрибутов и токенов, плюс
  `title-en` и `group-en`.
- Нужен символ `i-p-<имя>` в `assets/sprite.svg` — иначе сборка сайта падает с
  «нет символа в спрайте». Рисуйте на сетке `viewBox="0 0 16 16"`, обводкой,
  в стиле соседей.
- Добавив символ, поправьте их число в `README.md` и `docs/start/install.md`.
- Если объявили `js:` — нужен и раздел «JS», и хотя бы один пример на JS.
- Пополните таблицы «Когда использовать» у **соседних** компонентов: новый
  класс почти всегда отбирает часть случаев у существующих, и их маршруты
  устаревают молча.

## Компонент интерактивный

- Зарегистрируйте его в `tools/cmd/targets/main.go`: без записи проверка целей
  нажатия его просто не увидит, а нарушение останется настоящим.
- Поля записи: `w`, `h` — токены размера; `gap` — собственный зазор компонента
  (работает исключение по расстоянию из WCAG 2.5.8); `hit` + `alone: true` —
  если цель дорастает до нормы невидимой областью и соседей у неё нет.
- Носитель состояния берите из тех, что кит уже использует: `aria-selected`
  (18 мест), `aria-current`, `aria-checked`, `aria-expanded`, `aria-disabled`,
  `aria-busy`, `aria-invalid`, `aria-sort`. **`aria-pressed` в ките не
  встречается ни разу** — заводить его значит добавить ещё один способ сказать
  «включено».
- Клавиатура достаётся даром, если роль есть в `GROUPS` внутри `src/kit.js`:
  `listbox` · `tree` · `menu` · `radiogroup` · `tablist`. Список закрыт и
  совпадает с таблицей разметочного контракта в конституции — добавили строку
  там, добавьте и здесь.
- Ось перебора у `listbox` и `tree` по умолчанию вертикальная. Горизонтальному
  ряду нужен `aria-orientation="horizontal"`, иначе стрелки повесятся на `↑` `↓`.

## Тени

Отдельная тема с принятым решением: **ось рельефа делается после миграции.**
Смыслов у тени ровно два — «оторван от плоскости» (поповер, модалка) и
«имеет толщину» (контрол), и это записано в `tokens.css`. Третий смысл без
такой же записи заводить нельзя.

Переключатель `data-relief="flat" | "raised"` соберём из диффа против
коммита `1267d51`, где рельефное состояние ещё было умолчанием. Пока миграция
идёт — работаем только на плоском: это единственная ветка, у которой есть
эталон.

## Порядок запуска

```bash
go -C tools run ./cmd/dist        # первым: он же ловит несбалансированные скобки
go -C tools run ./cmd/contrast
go -C tools run ./cmd/targets
go -C tools run ./cmd/proportion
go -C tools run ./cmd/docscheck
go -C site   run ./cmd/site       # последним: контракт страниц и спрайта
```

Сайт обслуживается из `site/dist/`, куда исходники **копируются** при сборке.
После правки `src/` сервер предпросмотра надо пересобрать, иначе смотрите
старое.
