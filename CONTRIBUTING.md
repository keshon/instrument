# Разработка

Документ для тех, кто правит сам instrument. Как подключить библиотеку к
приложению — в [установке](docs/start/install.md).

## Структура репозитория

В репозитории две независимые части. У библиотеки сборки нет; сборка есть
только у сайта документации.

```
VERSION     номер версии. Один источник для dist/ и CHANGELOG
src/        исходники библиотеки. Правится он, а не собранное
dist/       собранный CSS и JS. Вывод, но лежит в репозитории: он же уезжает
            в npm и на CDN
assets/     спрайт иконок, логотип
docs/       страницы документации: markdown с frontmatter
            перевод — соседний файл: button.md → button.en.md
site/       генератор сайта на Go: cmd/site, internal/, шаблоны, ресурсы
site/dist/  собранный сайт. Вывод, в .gitignore
tools/      проверки
```

Файлы исходника и их содержимое перечислены в
[README](README.md#что-внутри), порядок слоёв — в
[токенах](docs/foundations/tokens.md).

## Сборка сайта

```bash
# собрать и поднять сервер
go -C site run ./cmd/site -serve :4321

# только собрать
go -C site run ./cmd/site
```

`-serve` поднимает файловый сервер над готовым `site/dist`. Автосборки нет:
после правки исходников сервер нужно перезапустить.

Сборка падает на битой ссылке, неразвёрнутой ограде примера, отсутствующем
символе спрайта и пустом кадре.

## Проверки

```bash
go -C tools run ./cmd/contrast    # контраст пар токенов против порогов WCAG
go -C tools run ./cmd/targets     # цели нажатия против WCAG 2.2 AA в 3 плотностях
go -C tools run ./cmd/proportion  # отношения размеров: кегли, глифы, форма контрола
go -C tools run ./cmd/docscheck   # документация против библиотеки, в обе стороны
go -C tools run ./cmd/dist        # собрать dist/ (-check — сверить с src/)
```

Все пять читают текст: `tokens.css`, страницы документации, собранные файлы.
Они дёшевы, работают без браузера и ловят расхождение до того, как оно доедет
до экрана. Того, что сложилось на экране после вложенности и полупрозрачных
слоёв, они не видят — это меряет
[проверка по пикселям](docs/about/audit.md), и запускать её нужно вручную, в
браузере.

Все пять запускаются на каждый push и каждый pull request —
[`.github/workflows/ci.yml`](.github/workflows/ci.yml). Туда же входят
`go vet` и `gofmt`. Публикация сайта — отдельная работа, зависящая от
проверок, и только с ветки по умолчанию.

### Что сверяет `docscheck`

В обе стороны:

- **вперёд** — в примере стоит класс, которого в библиотеке нет. Это ошибка,
  проверка падает;
- **назад** — класс есть, страницы у него нет. Это метрика, проверка не
  падает.

Заодно сверяются значения `data-*` атрибутов против словарей, вынутых из CSS,
и имена токенов. Словари закрыты: значение вне словаря и несуществующий токен
не дают ошибки в браузере, они просто ничего не делают.

Проверка не отличает разметку в примере от разметки, упомянутой в прозе.
Опечатку в тексте страницы она тоже посчитает ошибкой.

## Как добавить компонент

0. **Дыра должна проявиться на двух разных настоящих экранах** — не в примере
   документации. Один экран доказывает вкус этого экрана, два — что форма
   повторяется.

1. **Ответьте, какую работу делает элемент.** Панель — область приложения.
   Карточка — объект, который можно было бы перетащить. Строка очереди
   плоская, шаг имеет тело. Если ответа нет, нужен существующий компонент с
   другим содержимым.

2. **Возьмите высоту, отступ и размер из яруса ролей.** Новое значение
   заводится токеном, а не константой внутри компонента: константа сломает
   плотность.

3. **Опишите варианты через 2–3 внутренние переменные** (`--btn-fg`,
   `--btn-bg`), а не переписыванием правила. Если базовое правило пишет
   `background` напрямую, переменная не читается и вариант перестаёт быть
   двумя строками.

4. **Состояния меняют только поверхность и рамку.** Наведение не двигает
   раскладку, не меняет кегль и не добавляет тень.

5. **Прогоните `go -C tools run ./cmd/contrast`** и добавьте туда свои пары.

6. **Проверьте в трёх плотностях.** Компонент, ломающийся в `compact`, несёт
   зашитую константу.

7. **Проверьте, что комментарий описывает код.**

Правила, которым обязан следовать результат, — в
[принципах дизайна](docs/about/design-principles.md).

## Выпуск

Версия объявлена в `VERSION`, и `package.json` обязан её повторять:
расхождение валит `cmd/dist`. Шапку `dist/` печатает `VERSION`, а в реестр
уезжает `package.json` — при расхождении на CDN оказывается файл, который
называет себя не так, как пакет вокруг него.

```bash
# 1. поднять номер в VERSION и package.json, затем
go -C tools run ./cmd/dist          # пересобрать поставку
go -C tools run ./cmd/dist -check   # и сверить её с src/

# 2. тег: по нему jsDelivr отдаёт файл прямо из GitHub, без npm
git tag v0.6.2 && git push --tags

# 3. реестр
npm publish
```

`npm pack --dry-run` показывает состав пакета. Смотреть до публикации:
версию в npm нельзя перезаписать, только выпустить следующую.

После выпуска обновляется CDN-ссылка в [README](README.md) и на
[главной странице сайта](docs/index.md).
