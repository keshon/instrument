# Разработка

Документ для тех, кто правит сам instrument. Как подключить библиотеку к
приложению — в [установке](docs/start/install.md).

## Структура репозитория

В репозитории две независимые части. У библиотеки сборки нет; сборка есть
только у сайта документации.

```
VERSION     номер версии. Один источник для dist/ и CHANGELOG
src/        исходники библиотеки. Правится он, а не собранное
dist/       собранный CSS и JS. Вывод, но лежит в репозитории: он же уезжает
            в npm и на CDN
assets/     спрайт иконок, логотип
docs/       страницы документации: markdown с frontmatter
            перевод — соседний файл: button.md → button.en.md
site/       генератор сайта на Go: cmd/site, internal/, шаблоны, ресурсы
site/dist/  собранный сайт. Вывод, в .gitignore
tools/      проверки
```

Файлы исходника и их содержимое перечислены в
[README](README.md#что-внутри), порядок слоёв — в
[токенах](docs/foundations/tokens.md).

## Сборка сайта

```bash
# собрать и поднять сервер
go -C site run ./cmd/site -serve :4321

# только собрать
go -C site run ./cmd/site
```

`-serve` поднимает файловый сервер над готовым `site/dist`. Автосборки нет:
после правки исходников сервер нужно перезапустить.

Сборка падает на битой ссылке, неразвёрнутой ограде примера, отсутствующем
символе спрайта и пустом кадре.

## Проверки

```bash
go -C tools run ./cmd/contrast    # контраст пар токенов против порогов WCAG
go -C tools run ./cmd/targets     # цели нажатия против WCAG 2.2 AA в 3 плотностях
go -C tools run ./cmd/proportion  # отношения размеров: кегли, глифы, форма контрола
go -C tools run ./cmd/docscheck   # документация против библиотеки, в обе стороны
go -C tools run ./cmd/registry    # реестр компонентов против сквозных списков CSS
go -C tools run ./cmd/dist        # собрать dist/ (-check — сверить с src/)
```

На Windows то же самое одной командой — `check.bat` в корне:

```
check              все проверки разом, как в CI
check proportion   одна из них
check serve        собрать сайт и поднять сервер на :4322
check pixels       проверка по отрисованным пикселям
```

Второго списка проверок он не заводит: строка, добавленная в `check.bat`,
обязана появиться и в `ci.yml`, иначе локально зелено, а на push красно.

Все шесть читают текст: `tokens.css`, страницы документации, реестр, собранные
файлы.
Они дёшевы, работают без браузера и ловят расхождение до того, как оно доедет
до экрана. Того, что сложилось на экране после вложенности и полупрозрачных
слоёв, они не видят — это меряет
[проверка по пикселям](docs/about/audit.md), и запускать её нужно вручную, в
браузере.

`cmd/dist` перед сборкой сверяет баланс фигурных скобок в каждом файле `src/`.

`cmd/dist` там же сверяет **ярус ролей**: просвет не имеет права брать крупную
ступень шкалы напрямую. Правило «компоненты берут отсюда только через ярус
ролей» держалось на честном слове и однажды сломалось — `.inst-stack--loose`
нёс `gap: var(--space-7)`, потому что роли на просвет между разделами не
существовало. Роль завелась, обход убран, теперь его стережёт гейт.

`cmd/proportion` кроме перцептивных полос проверяет один ТОЧНЫЙ инвариант:
`--gap-section` обязан быть ровно вчетверо больше `--gap-row` во всех
пятнадцати ячейках. Это не подобранное число, а вывод: шкала устроена так, что
подъём на четыре ступени даёт ×4 в каждой точке.
Лишняя `}` закрывает не правило, а блок `@layer`, в который импорт вкладывает
файл: остаток файла оказывается вне слоёв и начинает выигрывать у стилей
приложения, `prefers-reduced-motion` и `@media print`. Через `@import` в
браузере это не видно — лишняя скобка на верхнем уровне отбрасывается
парсером, — и сверка `dist/` с `src/` тоже молчит: скобка стоит в обоих.

Все шесть запускаются на каждый push и каждый pull request —
[`.github/workflows/ci.yml`](.github/workflows/ci.yml). Туда же входят
`go vet` и `gofmt`. Публикация сайта — отдельная работа, зависящая от
проверок, и только с ветки по умолчанию.

### Что сверяет `docscheck`

Кроме существования классов и токенов он сверяет **значения** в таблицах
`docs/foundations/tokens.md` с объявлениями в `tokens.css`. Это другой род
ошибки: класс на месте, токен на месте, врёт только число — и до этой проверки
такое расхождение жило до тех пор, пока кто-нибудь не сверял руками.

Разбираются лишь машиночитаемые ячейки: ссылка на другой токен (`` `--n-2` ``)
и запись вида «чёрный 3.5%». Проза вроде «`--a-4` 14%, в обеих темах»
пропускается молча — заставлять таблицу быть машиночитаемой целиком значило бы
её выхолостить.


В обе стороны:

- **вперёд** — в примере стоит класс, которого в библиотеке нет. Это ошибка,
  проверка падает;
- **назад** — класс есть, страницы у него нет. Это метрика, проверка не
  падает.

Заодно сверяются значения `data-*` атрибутов против словарей, вынутых из CSS,
и имена токенов. Словари закрыты: значение вне словаря и несуществующий токен
не дают ошибки в браузере, они просто ничего не делают.

Проверка не отличает разметку в примере от разметки, упомянутой в прозе.
Опечатку в тексте страницы она тоже посчитает ошибкой.

### Реестр компонентов — `components.json`

Сквозные оси записаны в CSS перечислением имён: список печати, список
forced-colors, список замедления. Каждый надо править руками при добавлении
компонента, забытая запись не даёт ошибки в браузере, и до `cmd/registry` за
ними не следило ничего.

**В реестре лежит только то, чего нельзя вывести из исходников.** Какие классы
существуют, в каком они файле, какие токены читают, есть ли страница — всё это
добывается обходом; продублированный факт расходится с оригиналом молча.
Отображение «класс → компонент» тоже не хранится: оно уже объявлено во
frontmatter страниц, и `docscheck` сторожит его полноту. Реестр называет
компонент, а классы за него называет документация.

Остаётся решение автора — четыре оси, и все четыре обязательны:

| Ось | Значения | Что решает |
|---|---|---|
| `flow` | `inline` · `block` | Меряется содержимым или занимает ширину колонки |
| `print` | `keep` · `hide` | Печатается или это хром приложения |
| `page` | `flow` · `whole` | Может ли разорваться между листами |
| `forced` | `none` · `border` · `fill` · `selection` · `glyph` | Что с ним делает высокий контраст |

Базовое значение пишется явно: пропуск и осознанное «ничего не нужно» обязаны
различаться, иначе проверка превращается в пожелание. Политика за часть
компонента объявляется в `parts` и только его владельцем — тем, чья страница
назвала класс первой.

```json
"segmented": {
  "axes": { "flow": "inline", "print": "hide", "page": "flow", "forced": "none" }
}
```

Отдельной схемы JSON нет намеренно: словарь значений живёт в `cmd/registry`, и
второе его объявление разошлось бы с первым — ровно та болезнь, против которой
реестр и заведён.

Там же лежит **разметочный контракт** — то, что обязан написать автор
разметки, чтобы роль не оказалась пустым обещанием. Поле `roving` говорит, кто
расставляет бегущий `tabindex`: `author` там, где группа видна сразу
(сегментированный, очередь, дерево, вкладки), `js` там, где до открытия она в
обход не попадает (меню в поповере).

```json
"segmented": {
  "aria": {
    "role": "radiogroup", "roving": "author", "requires": ["aria-label"],
    "item": { "role": "radio", "state": "aria-checked" }
  }
}
```

Сверяется это по **живым примерам страниц**, а не по CSS, и место выбрано
намеренно: пример — то, что читатель копирует к себе, поэтому пример,
забывший обязательный атрибут, расходится тиражом. Он же и есть исполняемый
тест компонента: другого у кита нет, и заводить второй значило бы получить два
расходящихся описания.

Отдельно сверяются роли: словарь `GROUPS` в `instrument.js` и роли реестра
обязаны совпадать в обе стороны. Роль, которую скрипт обслуживает молча,
обещает клавиатуру от имени кита; роль, объявленная без поддержки скрипта,
обещает её впустую.

**Чего в реестре нет и не будет.** Замедление при `prefers-reduced-motion`
**выводится**: замедлять надо ровно то, у чего бесконечная анимация. Проверка
сверяет список `motion.css` с этим выводом и реестр не спрашивает. Ось, которую
можно вывести, не заводится.

## Как добавить компонент

0. **Дыра должна проявиться на двух разных настоящих экранах** — не в примере
   документации. Один экран доказывает вкус этого экрана, два — что форма
   повторяется.

1. **Ответьте, какую работу делает элемент.** Панель — область приложения.
   Карточка — объект, который можно было бы перетащить. Строка очереди
   плоская, шаг имеет тело. Если ответа нет, нужен существующий компонент с
   другим содержимым.

2. **Возьмите высоту, отступ и размер из яруса ролей.** Новое значение
   заводится токеном, а не константой внутри компонента: константа сломает
   плотность.

3. **Опишите варианты через 2–3 внутренние переменные** (`--btn-fg`,
   `--btn-bg`), а не переписыванием правила. Если базовое правило пишет
   `background` напрямую, переменная не читается и вариант перестаёт быть
   двумя строками.

4. **Состояния меняют только поверхность и рамку.** Наведение не двигает
   раскладку, не меняет кегль и не добавляет тень.

5. **Прогоните `go -C tools run ./cmd/contrast`** и добавьте туда свои пары.

6. **Проверьте в трёх плотностях и на крайних ступенях масштаба.** Компонент,
   ломающийся в `compact`, несёт зашитую константу; ломающийся на `18` — зашитый
   кегль или зашитую высоту.

7. **Заведите запись в [`components.json`](components.json)** — четыре оси, все
   обязательны, базовое значение пишется явно. Без неё `cmd/registry` не даст
   собрать: компонент, о котором не решили, печатается ли он и что с ним делает
   высокий контраст, — это компонент, который однажды выйдет на бумагу шапкой
   приложения.

8. **Проверьте, что комментарий описывает код.**

Правила, которым обязан следовать результат, — в
[принципах дизайна](docs/about/design-principles.md).

## Выпуск

Версия объявлена в `VERSION`, и `package.json` обязан её повторять:
расхождение валит `cmd/dist`. Шапку `dist/` печатает `VERSION`, а в реестр
уезжает `package.json` — при расхождении на CDN оказывается файл, который
называет себя не так, как пакет вокруг него.

```bash
# 1. поднять номер в VERSION и package.json, затем
go -C tools run ./cmd/dist          # пересобрать поставку
go -C tools run ./cmd/dist -check   # и сверить её с src/

# 2. тег: по нему jsDelivr отдаёт файл прямо из GitHub, без npm
git tag v0.6.2 && git push --tags

# 3. реестр
npm publish
```

`npm pack --dry-run` показывает состав пакета. Смотреть до публикации:
версию в npm нельзя перезаписать, только выпустить следующую.

После выпуска обновляется CDN-ссылка в [README](README.md) и на
[главной странице сайта](docs/index.md).
