# Расширение области: дашборды, админки, веб-приложения

Аудит покрытия на 2026-08-05. Что в ките есть, чего не хватает, и в каком
порядке это строить. Только компоненты, не требующие JS.

Инвентаризация: 139 классов и модификаторов, из них 22 — агентный слой.

---

## Главный вывод

**Не хватает не компонентов. Не хватает возможности собрать страницу.**

В ките нет ни одного примитива раскладки. Ни одного. Оболочки приложения,
контейнера, сетки, стопки, ряда, боковой навигации, шапки страницы — нет
ничего. Всё это сейчас живёт в `<style>` живой спецификации как её
строительные леса: `.page`, `.grid2`, `.stack`, `.row`, `.narrow`, `.sub`.

То есть кит умеет нарисовать любой элемент внутри панели и не умеет
расположить сами панели. Для агентского инструмента это сходило с рук —
экран там один и его сверстали руками. Для админки, где экранов сорок, это
блокер: каждый экран будет городить свою раскладку, и через месяц их будет
сорок разных.

Это же объясняет, почему живая спецификация обросла лесами: по правилу «демо
не имеет права на инлайновое оформление» я вынес их в классы страницы, но
половина из них — не леса, а недостающие компоненты кита.

**Второй вывод.** Конституция врёт про JS. Строка «поповер, тултип и модалка —
им нужен JS» устарела: Popover API (`popover` + `popovertarget`) даёт верхний
слой, лёгкое закрытие и управление фокусом **полностью декларативно**, и это
Baseline с 2024 года. Значит, оверлеи переезжают из «нельзя без JS» в
«сегодня же».

## Что платформа умеет без JS

Проверено в Chrome 148. Разделено по риску, потому что одного движка мало.

| Возможность | Что даёт | Статус |
|---|---|---|
| `popover` + `popovertarget` | поповер, меню, шторка — верхний слой, лёгкое закрытие, фокус | **безопасно** (Baseline 2024) |
| `<details name>` | аккордеон с единственной открытой секцией | **безопасно** |
| `:user-invalid` / `:user-valid` | живая валидация формы без единой строки JS | **безопасно** |
| `@container` | панель перестраивается по своей ширине, а не по ширине окна | **безопасно** (Baseline 2023) |
| `subgrid` | сквозное выравнивание колонок вложенных строк | **безопасно** |
| `transition-behavior: allow-discrete` | появление и исчезновение поповера с переходом | **безопасно** |
| `anchor-name` / `position-area` | привязка поповера к триггеру без вычислений | **прогрессивно** — вне Chrome неровно, нужен запасной вариант |
| `field-sizing: content` | текстовое поле растёт по содержимому | **прогрессивно** |
| `interpolate-size: allow-keywords` | анимация раскрытия до `auto` | **прогрессивно** |
| `::details-content` | стилизация тела `<details>` | **прогрессивно** |
| `command` / `commandfor` | открытие `<dialog>` без JS | **прогрессивно** |
| `::scroll-button`, `scroll-marker-group` | карусель без JS | **прогрессивно**, и дашбордам не нужна |

Правило для кита: на «безопасном» строим компоненты, «прогрессивное»
используем только там, где отсутствие поддержки деградирует, а не ломает.

## Пробелы по ярусам

Ярус — это порядок необходимости, а не важности. Без яруса 0 остальные
бессмысленны.

### Ярус 0. Раскладка — без этого страницы нет

| Компонент | Работа |
|---|---|
| `.shell` | оболочка приложения: боковая колонка + шапка + рабочая область, независимая прокрутка областей |
| `.container` | ограничение ширины прозы и форм |
| `.stack` | вертикальный поток с шагом из `--gap-*` |
| `.cluster` | горизонтальная группа с переносом (кнопки, фильтры, теги) |
| `.grid` | адаптивная сетка карточек через `auto-fit` |
| `.split` | две области с фиксированной и резиновой |
| `.page-header` | заголовок экрана + описание + действия + крошки |
| `.section` | смысловой блок с заголовком и липким подзаголовком |
| `.scroll-area` | именованная область прокрутки вместо `overflow:auto` россыпью |

Девять компонентов, почти все — 5–15 строк. Это самый дешёвый и самый
недостающий ярус.

### Ярус 1. Навигация

| Компонент | Замечание |
|---|---|
| `.nav`, `.nav-item`, `.nav-group` | боковая навигация: иконка, подпись, счётчик, `aria-current` |
| `.crumbs` | крошки: `<nav><ol>`, разделитель псевдоэлементом, последняя — `aria-current="page"` |
| `.tabs` | на ссылках (переключение — это роутинг, JS не нужен); `role="tablist"` только если вкладки настоящие |
| `.pager` | постраничная навигация ссылками, текущая, многоточие |
| `.steps` | мастер: пронумерованные шаги, состояния «пройден / текущий / впереди» |
| `.menu`, `.menu-item`, `.menu-sep` | содержимое поповера |
| `.toc` | оглавление длинной страницы |

### Ярус 2. Оверлеи — теперь без JS

| Компонент | Как |
|---|---|
| `.popover` | `[popover]` + `popovertarget`. Тень `--shadow-popover` наконец получает применение |
| `.menu` в поповере | выпадающее меню, лёгкое закрытие бесплатно |
| `.tooltip` | обёртка + `:hover`/`:focus-visible`; без API привязки, чтобы работало везде. Контракт: `aria-describedby` |
| `.dialog` | стилизация `<dialog>`; открытие пока JS (одна строка) или `commandfor` там, где есть |
| `.sheet` | шторка от края — тот же `<dialog>`, другая раскладка |

Это же закрывает давний долг: `--z-popover`, `--z-modal`, `--shadow-popover`,
`--shadow-modal` и `--surface-overlay` объявлены и не используются ни разу.

### Ярус 3. Формы — админка это на 70% формы

| Компонент | Замечание |
|---|---|
| `.form`, `.form-row` | раскладка: подпись сверху и подпись сбоку, колонка подписей общим токеном |
| `.input-group` | префикс и суффикс: валюта, единица, иконка поиска, кнопка вплотную |
| `.search` | `input[type=search]` с иконкой и очисткой |
| `.fieldset` | группа с легендой |
| `.form-actions` | липкая полоса действий внизу длинной формы |
| `.field` → `:user-invalid` | живая валидация средствами платформы; сейчас состояние ошибки ставится только руками через `aria-invalid` |
| `[readonly]` | сейчас неотличим от `[disabled]`, а это разные вещи: одно нельзя менять, другое неактивно |
| `.choice-card` | выбираемая карточка (радио или чекбокс внутри) — в админках повсеместно |
| `.file` | поле файла и зона перетаскивания (статическая часть) |

## Сквозные решения, которые надо принять до компонентов

Это не компоненты, но если их не решить сейчас, придётся переделывать сорок
штук вместо пяти.

**1. Адаптивность.** У кита её нет вообще: ни брейкпоинтов, ни контейнерных
запросов, ни одного `@media` по ширине. Для панельного кита правильный ответ
почти наверняка `@container`: панель должна перестраиваться по своей ширине,
а не по ширине окна, потому что одна и та же панель стоит и в узкой колонке
инспектора, и во всю ширину дашборда. Это архитектурное решение, и оно
должно быть принято до, а не после.

**2. Палитра графиков.** Категориальная последовательность фиксированного
порядка, выведенная из тех же рамп, с правилом: категориальный цвет не
является ни статусом, ни акцентом, и порядок в ней — часть контракта.
Одновременно нужен ответ на «а если серий больше восьми» (ответ: это не
график, это таблица).

**3. Префикс имён.** Уже отмечен как долг, но с выходом в админки риск
коллизии перестаёт быть теоретическим: `.table`, `.card`, `.input`, `.menu`,
`.nav`, `.tag`, `.avatar`, `.form` — это ровно те имена, которые есть у
любого приложения. Дешевле сделать сейчас, на 139 классах, чем на 250.

**4. Иконки.** В спрайте пять штук. Админке нужно 30–40, и нужен принцип
пополнения, иначе через месяц там будет три стиля обводки.

**5. Печать.** Ни одного правила `@media print`. Админки печатают отчёты и
таблицы, и сейчас на бумагу уйдут тёмные поверхности и обрезанные области
прокрутки.

**6. Пересмотреть два закона под новую область.**
«Тень только у поповера и модалки» — с появлением шторки и тоста надо явно
сказать, что они берут существующие две, а не заводят третью. «Один акцент» —
надо явно вынести категориальную палитру из-под этого запрета, иначе первый
же дашборд его нарушит.

## Что честно остаётся за JS

Чтобы не притворяться, что покрытие полное:

комбобокс и автодополнение · выбор даты сверх нативного · очередь тостов ·
перетаскиваемый разделитель панелей · виртуализация длинных списков ·
сортировка и фильтрация таблицы · загрузка файлов с прогрессом ·
бегущий `tabindex` для меню, вкладок и дерева · перетаскивание ·
редактирование на месте · графики с интерактивностью.

Стилевую часть каждого из них кит может дать заранее — поведение приезжает
со слоем приложения.

## Предлагаемый порядок

Четыре волны. Каждая самодостаточна и заканчивается работающим экраном.

**Волна 1 — раскладка и навигация. СДЕЛАНО.** `src/layout.css`, 41 класс:
оболочка, контейнер, стопка, кластер, сетка, сплит, шапка экрана, секция,
навигация, крошки, вкладки, пагинация, шаги мастера, пропуск к содержимому.
Приняты решения: адаптивность интринсик → `@container` → `@media` (в этом
порядке), классы без префикса, типографика в rem при геометрии в px.
`.scroll-area` из плана выброшен: `.panel-body`, `.shell-main`, `.log` и
`.code` уже прокручиваются сами, а дублирующий примитив — ровно то, против
чего правило «если ответа нет, компонент не нужен».

**Волна 2 — формы. СДЕЛАНО.** `src/forms.css`, 573 строки: раскладка формы
(подпись сверху и сбоку через общий `--label-col`), группа с приставками,
поиск с нативной очисткой, `fieldset`, липкая полоса действий, живая
валидация на `:user-invalid`, `readonly` против `disabled`, выбираемые
карточки, зона файла, нативные дата и время, множественный выбор,
пометки обязательности. Основы полей переехали из `components.css` —
все формовые концерны теперь в одном файле, слой тот же.

Попутно исправлено два дефекта, найденных проверкой: `.input:disabled`
красил текст серым вместо прозрачности (нарушение собственного закона
«кнопка сохраняет идентичность») и наведение перебивало рамку ошибки.

**Волна 3 — оверлеи и обратная связь. СДЕЛАНО.** `src/overlay.css` (поповер
с привязкой к вызвавшей кнопке, меню, тултип, модалка, шторка) и
`src/print.css`. Баннер и аккордеон — в `components.css`. Долг по
неиспользуемым токенам закрыт: обе тени, `--surface-overlay`, новый
`--scrim` и z-индексы наконец при деле.

Проверено: поповер открывается и закрывается без JS, привязывается к
вызвавшей кнопке через неявный якорь (под `@supports`, иначе по центру);
аккордеон на `<details name>` взаимоисключающий без JS; модалке нужна ровно
одна строка (`showModal`), закрытие декларативное.

**Волна 4 — данные. СДЕЛАНО.** `src/data.css` плюс расширение таблицы в
`components.css`: категориальная палитра на шесть рядов, сортировка с
`aria-sort` и значком направления, колонки выбора и действий, итоги,
липкая первая колонка, аватар и группа, тег, лента событий, легенда,
спарклайн, кольцо, календарь.

Палитра выведена как оговорённое исключение из первого закона и получила
собственные правила — порядок как контракт, отступ 25° от статусных тонов,
разная светлота ради дальтонизма и чёрно-белой печати, потолок в шесть
рядов.

Иконки пополняются в каждой волне под её нужды, а не отдельным заходом.
Каждая волна дописывает свои пары в `tools/contrast.mjs` и свои разделы в
живую спецификацию — иначе она не считается завершённой.
