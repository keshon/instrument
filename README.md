# instrument

CSS-кит для интерфейсов, которые показывают человеку работу машины: очереди
задач, прогоны, логи, инспекторы, состояния и неопределённость.

Без сборки, без зависимостей, без JavaScript. Подключается одной строкой.

```html
<link rel="stylesheet" href="src/kit.css">
```

```html
<div role="listbox" aria-label="Очередь агентов">
  <div class="inst-task" role="option" data-state="running"
       aria-selected="true" tabindex="0">
    <span class="inst-task-gutter"><span class="inst-dot"></span></span>
    <span class="inst-task-main">
      <span class="inst-task-title inst-u-truncate">Разбор карты высот</span>
      <span class="inst-task-sub">terrain/heightmap.ts · 4 файла</span>
    </span>
    <span class="inst-task-meta">2,1 с</span>
  </div>
</div>
```

Роли здесь не украшение: кит **рисует** состояние, но не выдумывает его.
`data-state` красит строку, `aria-selected` подсвечивает выбор, а без
`role="listbox"` и `role="option"` первое невалидно, а второе не озвучится.
Полный разметочный контракт — в [docs/about/design-principles.md](docs/about/design-principles.md).

---

## Для кого

Для дашбордов, админок и агентских инструментов — интерфейсов, где главное на
экране это **данные**, где сидят часами и где машина работает, а человек за ней
наблюдает.

Здесь есть то, чего нет в универсальных китах: очередь задач, шаг с телом,
запрос подтверждения, блок отказа, диф, дорожка параллельных прогонов, лог с
колонками, инспектор с числовыми полями, дерево.

**Для чего он не подходит.** Лендинги, магазины, контентные сайты. Кит
намеренно тихий: без градиентов, свечений, теней на карточках и жирных
начертаний. Заголовок капсом здесь запрещён правилом, а не отсутствует по
недосмотру.

## Что внутри

| Файл | Что |
|---|---|
| `tokens.css` | рампы, семантика, роли, шесть тем, три плотности |
| `base.css` | сброс, умолчания элементов, фокус, скроллбары, проза |
| `layout.css` | оболочка, контейнер, поток, шапка экрана, навигация |
| `components.css` | кнопки, поверхности, таблица, состояния |
| `forms.css` | поля, валидация, раскладка формы |
| `data.css` | аватар, тег, лента, легенда, спарклайн, кольцо, календарь |
| `overlay.css` | поповер, меню, тултип, модалка, шторка |
| `agent.css` | агентный слой и режим принудительных цветов |
| `motion.css` | `prefers-reduced-motion` |
| `print.css` | `@media print` |
| `kit.js` | поведение клавиатуры. Опционально, ничего не рисует |

Подключать по одному не нужно: `kit.css` объявляет порядок слоёв, а он и есть
гарантия того, что ничего не переопределит друг друга не в том порядке.

```
kit.tokens → kit.base → kit.layout → kit.components → kit.overlay
  → kit.agent → kit.motion → kit.print
```

**Стили приложения лежат вне слоёв и всегда выигрывают** — без `!important`.

## Темы и плотность

```html
<html data-theme="dark">           <!-- шесть тем, список ниже -->
<html>                              <!-- атрибута нет — тема по настройке ОС -->

<section data-density="compact">   <!-- compact | comfortable -->
```

Шесть тем — это **три ручки**, а не шесть копий семантики: тон нейтрали, сила
уклона и глубина тёмных поверхностей. Седьмая тема стоит одну строку.

Светлые различаются уклоном, тёмные — глубиной: на светлом фоне глаз ловит
температуру, на тёмном — насколько панель отделяется от страницы.

Плотность — атрибут **контейнера**, а не вариант компонента: один атрибут на
панели перенастраивает всё внутри неё.

## Доступность

Контраст проверяется машиной, а не на глаз:

```bash
go -C tools run ./cmd/contrast
```

**492 пары цветов против порогов WCAG в шести темах.** Инструмент читает
настоящий `tokens.css` и резолвит `var()`, `light-dark()` и `color-mix()` так
же, как браузер, поэтому разойтись с китом не может.

Кроме этого: `prefers-reduced-motion` (переходы схлопываются, но индикаторы
активности **замедляются, а не гаснут** — кит, вся работа которого показывать
занятость машины, обязан показывать её всегда), `forced-colors`, `@media print`.

**Клавиатура.** Роль — это обещание: `role="listbox"` говорит, что стрелки
работают. Обещание выполняет отдельный файл:

```html
<script type="module" src="src/kit.js"></script>
```

Бегущий `tabindex`, стрелки, `Home`/`End` для списка, дерева, меню,
радиогруппы и вкладок. Он **опционален и ничего не рисует** — только ставит
атрибуты, которые уже есть в разметочном контракте. Без него работает всё,
что не требует клавиатуры.

## Требования

Chrome 123+ · Safari 17.5+ · Firefox 120+

По `light-dark()`, `oklch()`, каскадным слоям, вложенности, `:has()` и единице
`lh`. Полифилов нет и не будет.

## Чего пока нет

Честнее сказать сейчас, чем обнаружится на второй день:

- **разметки в документации** — живая спецификация показывает компоненты, но
  почти нигде не показывает разметку. Этап 2 роадмапа;
- **тостов и очереди уведомлений**;
- **комбобокса, автодополнения, выбора даты** сверх нативного;
- **npm-пакета** — пока только копирование или сабмодуль. `package.json`
  в репозитории нет намеренно: публиковаться ещё рано;
- **английской документации**.

Полный список и порядок работ — [ROADMAP.md](ROADMAP.md).

## Разработка

В репозитории две независимые части, и путать их не нужно: **кит сборки не
имеет**, сборка есть только у документации.

```
src/        кит. Правится руками, подключается <link>, ничем не собирается
docs/       страницы документации: markdown с frontmatter
site/       генератор сайта на Go — cmd/site, internal/, шаблоны, ресурсы
site/dist/  собранный сайт. Вывод, а не источник: в .gitignore
tools/      проверки
index.html  живая спецификация: все компоненты на одном экране, без сборки
```

```bash
# собрать и поднять сервер
go -C site run ./cmd/site -serve :4321

# только собрать
go -C site run ./cmd/site

# проверки
go -C tools run ./cmd/contrast    # 492 пары цветов против порогов WCAG в 6 темах
go -C tools run ./cmd/targets     # цели нажатия против WCAG 2.2 AA в 3 плотностях
go -C tools run ./cmd/docscheck   # документация против кита, в обе стороны

# живая спецификация без сборки
python -m http.server 8321
```

Сборка сайта роняет себя сама: битая ссылка, неразвёрнутая ограда примера,
отсутствующий символ спрайта, пустой кадр. `docs-check` сверяет исходники, но
между исходником и страницей стоит генератор, и он ломает своё.

Всё это идёт на каждый push — `.github/workflows/ci.yml`. Проверка, которую
надо не забыть запустить, однажды не запустится.

`-serve` поднимает файловый сервер над готовым `dist`; автосборки нет, после
правки исходников его надо перезапустить.
