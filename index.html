Подключать по одному не нужно и не стоит: kit.css объявляет порядок слоёв, а он и есть гарантия того, что ничего не переопределит друг друга не в том порядке.

Слои и почему ваши стили всегда выигрывают

@layer kit.tokens, kit.base, kit.layout, kit.components, kit.overlay, kit.agent, kit.motion, kit.print;

Стили приложения лежат вне слоёв, а неслойное объявление выигрывает у любого слойного независимо от специфичности. Значит, переопределять кит можно обычным правилом — !important не нужен нигде. Обратная сторона: случайное совпадение имени класса тоже выиграет молча, поэтому за пределами своих продуктов классам нужен префикс.

Тема и плотность

<html data-theme="dark"> <!-- light | light-cool | dark | dark-soft --> <html> <!-- атрибута нет — тема по настройке ОС --> <section data-density="compact"> <!-- compact | comfortable -->

Плотность — атрибут контейнера, а не вариант компонента: один атрибут на панели перенастраивает всё внутри неё. Тема живёт на html и меняет ровно две вещи — тон нейтрали и глубину поверхностей.

Что обязательно в разметке

Кит рисует состояние, но не выдумывает его. Списочные компоненты требуют ролей, иначе aria-selected невалиден, а с клавиатуры до них не добраться: очередь — role="listbox" и role="option", дерево — role="tree" и role="treeitem", мера — role="progressbar" с aria-valuenow, сегментированный — role="radiogroup". Полный список — в DESIGN.md.

Проверка

node tools/contrast.mjs

328 пар цветов против порогов WCAG в четырёх темах. Инструмент читает настоящий tokens.css и резолвит var(), light-dark() и color-mix() так же, как браузер, поэтому разойтись с китом не может. Заводите новый семантический токен — добавьте туда его пары.

Минимум браузера: Chrome 123+, Safari 17.5+, Firefox 120+ — по light-dark(), oklch(), каскадным слоям, вложенности, :has() и единице lh.

Цвет

Два слоя. Внизу — рампы: сырые шаги, они не меняются никогда. Сверху — семантика: для чего цвет нужен. Семантика объявлена один раз через light-dark(), поэтому второй темы как отдельного блока не существует — и расходиться нечему. Компонент имеет право обращаться только к семантике; тот, кто написал --n-3, только что захардкодил светлую тему.

Нейтральная рампа — 15 шагов, лёгкий тёплый уклон

Пятнадцатый шаг существует не для красоты: тёмной теме нужно четыре различимые поверхности подряд, а на четырнадцати их помещалось три.

Два токена на тон, а не три

У каждого смыслового тона ровно два токена: --*-text для метки — текста, точки состояния, заливки меры — и --*-bg для тонированного фона под ней. Третьего, «заливки» между ними, нет намеренно: метка обязана держать порог и на поверхности, и на приглушённой дорожке, а это одно и то же требование, самое жёсткое. Проверка лежит в tools/contrast.mjs: она читает настоящий tokens.css и резолвит его как браузер, поэтому разойтись с китом не может.

Ритм и форма

Шаг 4px, шкала нарочно разрежена сверху — чтобы «чуть побольше» просто не было в наборе. Компоненты берут отступы не из шкалы напрямую, а из яруса ролей (--pad-panel, --gap-row, --size-dot): именно он даёт плотности одну точку, через которую она перенастраивает всё сразу.

Радиусы вложены: у внутреннего меньше, иначе он выпирает

Раскладка

Ярус, которого не было. Кит умел нарисовать что угодно внутри панели и не умел расположить сами панели — оболочка, сетка и стопка жили в лесах этой страницы, то есть у каждого нового экрана была бы своя раскладка.

Адаптивность строится тремя уровнями, и порядок в них важен. Интринсик — раскладка перестраивается сама, без единого запроса; так работают сетка и сплит ниже. @container — компонент отвечает на ширину своей области, а не окна: одна и та же панель стоит и в узкой колонке инспектора, и во всю ширину дашборда. @media — только оболочка, потому что она единственная действительно зависит от размера окна.

Кнопки

По умолчанию кнопка тихая. Экран, где всё primary, не имеет primary вовсе. Ховер меняет только --btn-bg, поэтому вариант — действительно две строки. У сплошной кнопки заливка при наведении уходит от цвета подписи: зеркальное «в тёмной светлее» роняло контраст подписи до 2.61.

Размеры завязаны на один токен высоты

Шов группы — снятая рамка у соседа, а не отрицательное поле в -0.5px: браузер никогда не рисует рамку тоньше физического пикселя, поэтому сдвиг на полпикселя оставлял видимое утолщение на каждом стыке.

Занятая кнопка

Занятость живёт на aria-busy, а не на своём атрибуте: у кнопки нет жизненного цикла, как у строки очереди, — есть переходный флаг «действие пошло», и слово для него платформа уже придумала. Подпись не убирается из потока, а гасится цветом: ширина остаётся прежней, иначе полоса действий дёргается ровно в тот момент, когда пользователь смотрит на курсор. Скринридеру подпись при этом остаётся. Кнопка намеренно сохраняет фокус: disabled выбросил бы её из порядка обхода прямо под пальцами у того, кто пришёл с клавиатуры. pointer-events снимает только мышь — защита от повторного нажатия живёт в обработчике, потому что это поведение, а не оформление.

Поля ввода

Поле стоит во врезе (--surface-field), а не на цвете панели: иначе на панели его единственной границей остаётся рамка, и поле приходится искать. Врез — отдельная роль поверхности, поэтому рамка может оставаться тихой. Подсказка и ошибка занимают один слот: ошибка заменяет подсказку, а не сдвигает форму вниз, — форма не перекладывается в момент заполнения.

Формы

Админка — это на 70% формы. Два правила, которым здесь подчиняется всё: валидацию показывает платформа, а readonly и disabled — это разные вещи. Одно нельзя изменить, но можно прочитать и скопировать; другое недоступно целиком. Пока они выглядели одинаково, пользователь не мог понять, ждать ему разблокировки или значение неизменяемо в принципе.

Подпись сверху и подпись сбоку

Выбор не вкусовой. Сверху — когда поля разнородны и их читают по одному. Сбоку — когда полей много и они однотипны: колонка подписей превращает форму в таблицу, которую можно просканировать, не читая каждую строку. Колонка — тот же --label-col, что у инспектора.

Живая валидация

Используется :user-invalid, а не :invalid. Разница принципиальная: :invalid горит красным с первой секунды, ещё до того, как в поле что-то ввели, — форма встречает пользователя россыпью ошибок, которых он не совершал. Введите что-нибудь не похожее на почту и уведите фокус — ошибка появится и заменит подсказку в том же слоте, без перекладывания формы.

Три прохода расстановки ресурсов плюс запекание навмеша. Основное время ушло на валидацию путей, которая перезапускалась дважды.
Можно ли ограничить расход токенов?
Да, в параметрах проекта. Лимит проверяется перед стартом каждого агента, а не по факту — прогон не уйдёт в минус.
Что происходит с артефактами после удаления?
Удаляются вместе с прогоном. Резервная копия хранится семь суток, восстановление — через поддержку.

Метрики

Метрика — одно число, за которым следят. Если чисел много и их сравнивают между собой — это таблица, а не ряд метрик. Нарочно без рамок, на приглушённой поверхности: ряд метрик читается как одна группа; рамка вокруг каждой превращает четыре числа в четыре объекта. Единица измерения мельче и тише самого числа, потому что она часть числа, а не сосед.

export function decodeHeightmap(buf: ArrayBuffer): Float32Array {
  const view = new DataView(buf);
  const size = view.getUint32(0, true);
  const out = new Float32Array(size * size);
  for (let i = 0; i < out.length; i++) {
    out[i] = view.getUint16(4 + i * 2, true) / 65535;
  }
  return out;
}

export function sampleBilinear(map: Float32Array, size: number, x: number, y: number) {
  const x0 = Math.floor(x), y0 = Math.floor(y);
  const x1 = Math.min(x0 + 1, size - 1), y1 = Math.min(y0 + 1, size - 1);
  const fx = x - x0, fy = y - y0;
  return  map[y0 * size + x0] * (1 - fx) * (1 - fy)
        + map[y0 * size + x1] * fx * (1 - fy)
        + map[y1 * size + x0] * (1 - fx) * fy
        + map[y1 * size + x1] * fx * fy;
}

О проекте

instrument — кит для интерфейсов, которые показывают человеку работу машины: очереди задач и прогоны, логи и инспекторы, дашборды и админки. Дисциплина одна на всё — тихий утилитарный минимализм, отрендеренный плоско.

Как устроен
Четыре яруса токенов: рампы, семантика, роли, переменные компонента. Тема — две ручки, а не четыре набора значений. Плотность перенастраивает только ярус ролей, поэтому в компонентах нет ни одного зашитого размера.
Чем проверен
tools/contrast.mjs читает настоящий tokens.css и резолвит его так же, как браузер. 328 пар цветов против порогов WCAG в четырёх темах. Тест не дублирует значения — он их вычисляет, поэтому разойтись с китом не может.
Что нужно браузеру
Chrome 123+, Safari 17.5+, Firefox 120+ — по light-dark(), oklch(), каскадным слоям, вложенности, :has() и единице lh. Подключение — одна строка, сборки нет.

Авторство и условия

Собран в паре человеком и Claude (Opus 5). Половина правил в конституции появилась не из замысла, а из найденных багов: жёлтая точка на контрасте 1.92, колесо мыши, съеденное overscroll-behavior, разъезжающиеся колонки лога. Каждая находка дописывала правило — правила здесь пережили свои баги.

Внутренний проект, лицензия не выбрана. Имена классов без префикса, поэтому за пределами своих продуктов префикс придётся добавить.
