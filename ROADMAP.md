# instrument — план преобразования в публичный кит

Составлен 2026-08-06 по итогам аудита «кит как продукт». Предыдущие документы
закрывают другие вопросы и остаются в силе: `DESIGN.md` — конституция,
`docs/internal/REVIEW.md` — ревизия CSS (отработала),
`docs/internal/SCOPE.md` — план покрытия (выполнен).

Этот план — про то, чего те три не рассматривали: **кит как продукт, а не как
CSS**.

## Принцип плана

**Ни одна строка существующего CSS не переписывается.** Токены, слои, темы,
плотность, контраст — это актив, а не долг. Всё в плане — достройка вокруг
готового ядра.

Три следствия:

1. Порядок этапов задан **необратимостью**, а не важностью. Префикс идёт
   первым не потому, что он важнее документации, а потому, что после первой
   публикации его сделать уже нельзя.
2. Этап считается закрытым только по своему критерию готовности. «Почти» не
   считается — ровно как в `docs/internal/SCOPE.md`, где волна без своего раздела в
   спецификации не засчитывалась.
3. Всё, что можно проверить машиной, проверяется машиной. У кита уже есть эта
   культура (`tools/contrast.mjs`), и её надо распространить, а не завести
   заново.

### Три расхождения с тем, что планировалось

**Префикс `inst-`, а не `i-`.** Два аргумента, найденных при исполнении.
Первый: у кита **уже есть** префикс — keyframes зовутся `inst-pulse`,
`inst-fade`, `inst-spin`, `inst-blink`, `inst-sweep`. Классы на `i-` дали бы
два пространства имён вместо одного, то есть ровно тот дубликат, против
которого написан `DESIGN.md:32`. Второй: `i-*` — конвенция UnoCSS/Iconify
(`i-lucide-check`), и проект, взявший кит вместе с ними, получил бы `.i-btn`
рядом с `.i-mdi-home` в одном атрибуте.

**`sideEffects: ["*.css"]`, а не `false`.** Для CSS-пакета `false` — прямая
ошибка: сборщик имеет право выбросить стили как неиспользуемые.

**Классов 265, а не 200, и столкновений было 6, а не 1.** Наивный `grep` по
файлу давал загрязнённый список: `.w3` и `.org` приезжали из
`xmlns='http://www.w3.org/2000/svg'` внутри data-URI, `.tokens` и `.base` — из
имён файлов в комментариях, `.is-up` — из исторической справки. Поэтому был
написан `tools/classes.mjs`, который сначала вырезает комментарии, строки и
`url()`, и только потом ищет селекторы.

Из шести столкновений настоящим было одно (`.tag` — переприсвоение смысла).
Пять остальных — легитимное «леса подкручивают компонент кита внутри демо»
(`.shell-demo .inst-shell`, `.bad-bars .inst-meter-fill` и подобные) и после
префикса читаются однозначно.

## Этап 1. Единый язык состояния

**Срок: 2 недели. Дешевле на 265 классах, чем на 400.**

`DESIGN.md:246` объявляет два канала: вариант — модификатор `--`, состояние —
атрибут. По факту атрибутных словарей **пять**, и они не ортогональны:

```
data-tone      neutral | running | ok | warn | error
data-state     running | done | pending | failed | current | skipped |
               ok | warn | denied | indeterminate
data-polarity  good | bad | warn
data-kind      add | del
data-when      invalid
.inst-is-add .inst-is-del
```

`ok` и `warn` живут одновременно в трёх словарях. И есть прямое
самопротиворечие внутри одного файла: диф кодирует «добавлено/удалено» дважды —
`.inst-is-add`/`.inst-is-del` (`src/agent.css:198`) и `[data-kind="add"|"del"]`
(`src/agent.css:236`), в сорока строках друг от друга. Это ровно тот
«дубликат — будущее расхождение», против которого написан `DESIGN.md:32`.

- [ ] **1.1.** Свести к двум осям: `data-tone` — смысл (5 значений, закрытый
      словарь), `data-state` — фаза жизни.
- [ ] **1.2.** Упразднить `data-polarity` — это `data-tone`, применённый к дельте.
- [ ] **1.3.** Упразднить `.inst-is-add`/`.inst-is-del`, диф переходит на один канал.
- [ ] **1.4.** Пересмотреть `data-kind` и `data-when` — оставить только если
      найдётся работа, которой не делают первые два.
- [ ] **1.5.** Дописать размерную шкалу. Сейчас она несимметрична:
      `.inst-btn--sm/--lg` и `.inst-avatar--sm/--lg` полные, у `.inst-input` и
      `.inst-select` есть только `--sm`, у `.inst-textarea` размеров нет вовсе.
      Ярус ролей
      (`--control-h-lg`) уже объявлен — недостаёт двух строк CSS, а не
      архитектуры. Кнопка `lg` рядом с полем сегодня рассыпает форму.
- [ ] **1.6.** `.inst-btn` в состоянии загрузки. Самое частое состояние кнопки
      в интерфейсе, который ждёт машину, то есть ровно в этой предметной
      области. Контракт: `[data-state="running"]`, ширина не прыгает,
      `.inst-spinner` уже есть.
- [ ] **1.7.** Оба словаря зафиксировать в `DESIGN.md` как закрытые.

## Этап 2. Разметка везде

**Срок: 3 недели. Самый важный этап плана.**

Спецификация **показывает** компоненты и почти никогда не показывает разметку,
которая их производит. Чтобы собрать `.task` или `.approval`, разработчик
обязан открыть View Source файла на 2026 строк и глазами найти нужный кусок.

- [ ] **2.1.** Для каждого компонента — блок разметки рядом с демо, с кнопкой
      копирования.
- [ ] **2.2.** Для каждого — справочник **таблицами, не прозой**: классы,
      обязательная разметка, CSS-переменные, токены, data-атрибуты. Прозой API
      не документируется — её нельзя просмотреть по диагонали и нельзя
      проверить на полноту.
- [ ] **2.3.** Порядок на странице по шаблону ниже.
- [ ] **2.4.** Сетка состояний для каждого контрола: default · hover · focus ·
      active · disabled · readonly · invalid · loading.
- [ ] **2.5.** Иконка + текст. Сейчас иконочная кнопка показана только без
      текста — самая частая форма кнопки в админках не продемонстрирована.

### Шаблон страницы компонента

Порядок отражает **частоту обращения**, а не полноту: большинство визитов
заканчивается на первом экране.

```
  Имя компонента                              [Стабильно] v0.x
  Одна строка: какую работу делает
──────────────────────────────────────────────────────────────
  1. ЖИВОЙ ПРИМЕР        демо · [Разметка ▾] · [⧉ Копировать]
                         переключатели темы и плотности
  2. УСТАНОВКА           одна строка, всегда одинаковая
  3. КОГДА / КОГДА НЕ    две колонки: ✓ используйте · ✗ возьмите [X]
──────────────────────────────────────────────────────────────
  4. ВАРИАНТЫ            каждый — демо + разметка
  5. РАЗМЕРЫ             sm / md / lg
  6. СОСТОЯНИЯ           сетка всех состояний
  7. С ИКОНКОЙ           слева / справа / только иконка
  8. КОМПОЗИЦИИ          в группе, в тулбаре, в форме
──────────────────────────────────────────────────────────────
  9. СПРАВОЧНИК          таблицы: классы · разметка · переменные ·
                         токены · data-атрибуты
 10. ДОСТУПНОСТЬ         таблица клавиш · роли · что даёт приложение
 11. ПОЧЕМУ ТАК          ← существующие .why переезжают СЮДА
 12. СВЯЗАННОЕ           + ссылка на исходник с номером строки
```

**Одно решение здесь принципиально: `.why` уезжает вниз.** Тексты превосходны,
но сейчас стоят **перед** демо и между читателем и его задачей. Кто пришёл за
кнопкой — получает кнопку; кто пришёл понять систему — доскроллит. Это не
понижение их ценности, а признание, что у страницы два читателя с разной
частотой обращения.

**Готово, когда:** любой компонент можно применить, не открывая `src/*.css`.

### Структура сайта

```

    approval-flow · empty-states · error-states
```

Пять решений, отличающих это от нынешней структуры:

1. **Foundations, а не Tokens** — сюда ходят дизайнеры, слово «токены» их отсекает.
2. **Agent — верхний уровень.** Это то, ради чего кит стоит брать: `.task`,
   `.step`, `.approval`, `.failure`, `.diff`, `.lane`, `.budget` нет ни у
   shadcn, ни у Radix, ни у Mantine, ни у MUI, ни у Ant Design.
3. **Patterns существует.** Сейчас нет ни одного собранного экрана.
4. **Accessibility — секция**, а не примечания в `.why`.
5. **Density в Foundations.** Одна из двух уникальных архитектурных идей кита
   сейчас существует как безымянный переключатель в шапке.

**Готово, когда:** у каждого компонента свой URL, работает поиск, `index.html`
перестал быть монолитом.

## Этап 4. Клавиатура

**Срок: 2 недели.**

`DESIGN.md:243` честно выносит бегущий `tabindex` в слой приложения. Но
следствие: `.task`, `.tree`, `.segmented`, `.menu`, `.tabs` в поставке
**недоступны с клавиатуры вообще** — `role="listbox"` без `tabindex` не
получает фокус.

Это хуже, чем «не сделано». Кит навязывает ARIA-роли и завязывает на них стили;
`role="listbox"` — обещание скринридеру, что стрелки работают. Компонент,
объявляющий роль и не выполняющий её контракт, обманывает вспомогательную
технологию.

- [ ] **4.1.** `packages/core/behavior/roving.js` — на основе уже написанной и
      корректной `wireRadioGroup` из `index.html`. Покрыть listbox, tree, menu,
      tabs. ~200 строк, автоинициализация по ролям, полностью опциональная.
- [ ] **4.2.** Touch targets. WCAG 2.2 AA требует 24×24. Провалы:
      `.tag-remove` — интерактивная кнопка `--size-chevron`, то есть **10×10 во
      всех плотностях**; в `compact` всё размеренное `sm`/`xs` уходит ниже
      нормы (`--control-h-sm: 22px`, `--control-h-xs: 18px`).
      Чинить областью нажатия через `::before { inset: -7px }` — форма не
      меняется, цель вырастает.
- [ ] **4.3.** `tools/targets.mjs` — проверка целей по всем трём плотностям,
      рядом с контрастом.
- [ ] **4.4.** Раздел Accessibility: заявить WCAG 2.2 AA, таблица клавиш по
      компонентам, отчёт контраста прямо на странице.

**Готово, когда:** каждая объявленная роль выполняет свой контракт, и это
проверено машиной.

Два замечания к разбиению:

**`components.css` — 1049 строк**, и внутри всё: кнопки, панели, таблица со

1049/656/281 строк соревнуются по специфичности и порядку импорта.

  дифференциатор.

  контейнерного запроса надо назвать токеном** — сейчас он вписан числом.

- **Сборка для подключения кита.** Одна строка `<link>` — реальное
