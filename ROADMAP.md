## Принцип плана

**Ни одна строка существующего CSS не переписывается.** Токены, слои, темы,
плотность, контраст — это актив, а не долг. Всё в плане — достройка вокруг
готового ядра.

Три следствия:

1. Порядок этапов задан **необратимостью**, а не важностью. Префикс идёт
   первым не потому, что он важнее документации, а потому, что после первой
   публикации его сделать уже нельзя.
2. Этап считается закрытым только по своему критерию готовности. «Почти» не
   считается — ровно как в `docs/internal/SCOPE.md`, где волна без своего раздела в
   спецификации не засчитывалась.
3. Всё, что можно проверить машиной, проверяется машиной. У кита уже есть эта
   культура (`tools/contrast.mjs`), и её надо распространить, а не завести
   заново.

### Три расхождения с тем, что планировалось

**Префикс `inst-`, а не `i-`.** Два аргумента, найденных при исполнении.
Первый: у кита **уже есть** префикс — keyframes зовутся `inst-pulse`,
`inst-fade`, `inst-spin`, `inst-blink`, `inst-sweep`. Классы на `i-` дали бы
два пространства имён вместо одного, то есть ровно тот дубликат, против
которого написан `docs/about/design-principles.md:32`. Второй: `i-*` — конвенция UnoCSS/Iconify
(`i-lucide-check`), и проект, взявший кит вместе с ними, получил бы `.i-btn`
рядом с `.i-mdi-home` в одном атрибуте.

**`sideEffects: ["*.css"]`, а не `false`.** Для CSS-пакета `false` — прямая
ошибка: сборщик имеет право выбросить стили как неиспользуемые.

**Классов 265, а не 200, и столкновений было 6, а не 1.** Наивный `grep` по
файлу давал загрязнённый список: `.w3` и `.org` приезжали из
`xmlns='http://www.w3.org/2000/svg'` внутри data-URI, `.tokens` и `.base` — из
имён файлов в комментариях, `.is-up` — из исторической справки. Поэтому был
написан `tools/classes.mjs`, который сначала вырезает комментарии, строки и
`url()`, и только потом ищет селекторы.

Из шести столкновений настоящим было одно (`.tag` — переприсвоение смысла).
Пять остальных — легитимное «леса подкручивают компонент кита внутри демо»
(`.shell-demo .inst-shell`, `.bad-bars .inst-meter-fill` и подобные) и после
префикса читаются однозначно.

## Этап 1. Единый язык состояния

**СДЕЛАНО 2026-08-06.** Было дешевле на 265 классах, чем на 400.

`docs/about/design-principles.md:246` объявляет два канала: вариант — модификатор `--`, состояние —
атрибут. По факту атрибутных словарей **пять**, и они не ортогональны:

```
data-tone      neutral | running | ok | warn | error
data-state     running | done | pending | failed | current | skipped |
               ok | warn | denied | indeterminate
data-polarity  good | bad | warn
data-kind      add | del
data-when      invalid
.inst-is-add .inst-is-del
```

`ok` и `warn` живут одновременно в трёх словарях. И есть прямое
самопротиворечие внутри одного файла: диф кодирует «добавлено/удалено» дважды —
`.inst-is-add`/`.inst-is-del` (`src/agent.css:198`) и `[data-kind="add"|"del"]`
(`src/agent.css:236`), в сорока строках друг от друга. Это ровно тот
«дубликат — будущее расхождение», против которого написан `docs/about/design-principles.md:32`.

- [x] **1.1.** Словари объявлены закрытыми и перечислены в `docs/about/design-principles.md`.
- [x] **1.2.** `data-polarity` упразднён → `data-tone`.
- [x] **1.3.** `.inst-is-add`/`.inst-is-del` упразднены, диф на одном канале.
- [x] **1.4.** `data-kind` и `data-when` оставлены — работа нашлась, см. ниже.
- [x] **1.5.** Дописать размерную шкалу. Сейчас она несимметрична:
      `.inst-btn--sm/--lg` и `.inst-avatar--sm/--lg` полные, у `.inst-input` и
      `.inst-select` есть только `--sm`, у `.inst-textarea` размеров нет вовсе.
      Ярус ролей
      (`--control-h-lg`) уже объявлен — недостаёт двух строк CSS, а не
      архитектуры. Кнопка `lg` рядом с полем сегодня рассыпает форму.
- [x] **1.6.** `.inst-btn` в состоянии загрузки — на `aria-busy`, не на
      `data-state`, см. ниже.
- [x] **1.7.** Словари зафиксированы в `docs/about/design-principles.md` как закрытые.

**Готово:** любое состояние любого компонента записывается ровно одним
способом, и этот способ перечислим.

### Два расхождения с тем, что планировалось

**Словарей четыре, а не два — и это не отступление, а уточнение диагноза.**
План требовал «свести к двум осям». Чтение кода показало, что проблема была не
в *числе* атрибутов, а в двух других вещах: дубликатах одной оси
(`data-polarity` против `data-tone`; `.is-add` против `data-kind`) и в том, что
ни один словарь не был закрыт. Осталось четыре, и каждый делает работу, которой
не делают остальные:

- `data-tone` — смысловой регистр, **один словарь на весь кит**;
- `data-state` — фаза жизни, **словарь свой у каждого компонента**, потому что
  у строки очереди и шага мастера разные фазы, и общий набор был бы либо
  неполон, либо бессмыслен;
- `data-kind` — категория: добавленная строка дифа не находится «в состоянии
  ok», она относится к виду «добавление», и тон здесь соврал бы;
- `data-when` — кто управляет показом: платформа по `:user-invalid` или
  приложение по ответу сервера. Это не состояние поля, а разделение
  ответственности.

Проверка, отличающая ось от дубликата, записана в конституцию: **если два
атрибута дают один и тот же цвет, это один атрибут с двумя именами.** Ровно по
ней ушёл `data-polarity` — `good`/`bad`/`warn` были третьим именем для
`ok`/`error`/`warn`, причём последнее совпадало буквально.

**Занятость кнопки — на `aria-busy`, а не на `data-state="running"`.** В ките
**уже** стояло `.inst-btn[aria-busy="true"] { pointer-events: none }` — половина
контракта без визуальной части. Добавить рядом `data-state` значило завести
второй канал ровно на том этапе, который каналы сокращает. У кнопки нет фазы
жизни, как у строки очереди: есть переходный флаг, и слово для него платформа
придумала.

### Что вскрылось по дороге

**Три значения `data-state` в разметке не имели ни одного правила в CSS:**
`todo` у шага мастера, `queued` у строки очереди, `approved` у запроса
подтверждения. Все три оказались базовыми — намеренно без оформления. Но пока
они нигде не объявлены, опечатка `data-state="quued"` выглядит ровно так же,
как база, и молча ничего не делает. Теперь базовые значения перечислены в
конституции наравне с остальными, и правило записано: значение заводится
вместе со строкой в таблице.

**Ещё два класса имеют CSS без демо:** `.inst-approval[data-state="denied"]` и
`.inst-task[data-state="warn"]`. В список покрытия этапа 2.

**Поле нельзя поставить в ряд по естественной ширине.** `.inst-input` и
`.inst-select-wrap` тянутся на 100%, поэтому в `.inst-cluster` каждый
выталкивает соседа на новую строку — демонстрация размеров потребовала лесов
(`.size-row`), как когда-то слайдер. Для формы полная ширина правильна, но
панель фильтров и строка поиска — это ряд. Кандидат в этап 5.

**Проверено:** 328 проверок контраста в 4 темах · ширина занятой кнопки
совпадает с обычной (86px против 86px) — полоса действий не дёргается ·
кольцо крутится теми же кадрами `inst-spin` и замедляется под
`prefers-reduced-motion` · в `forced-colors` дуга отделена от дорожки, иначе
равномерное кольцо не показывало бы вращения · поле, селект и кнопка одного
размера встают на одну высоту (26 / 32 / 38) · остатков `data-polarity` и
`.is-*` нет.

## Этап 2. Разметка везде

**СДЕЛАНО 2026-08-06.** Самый важный этап плана.

Спецификация **показывает** компоненты и почти никогда не показывает разметку,
которая их производит. Чтобы собрать `.task` или `.approval`, разработчик
обязан открыть View Source файла на 2026 строк и глазами найти нужный кусок.

- [ ] **2.1.** Для каждого компонента — блок разметки рядом с демо, с кнопкой
      копирования.
- [ ] **2.2.** Для каждого — справочник **таблицами, не прозой**: классы,
      обязательная разметка, CSS-переменные, токены, data-атрибуты. Прозой API
      не документируется — её нельзя просмотреть по диагонали и нельзя

- [ ] **2.3.** Порядок на странице по шаблону ниже.
- [ ] **2.4.** Сетка состояний для каждого контрола: default · hover · focus ·
      active · disabled · readonly · invalid · loading.
- [ ] **2.5.** Иконка + текст. Сейчас иконочная кнопка показана только без
      текста — самая частая форма кнопки в админках не продемонстрирована.

### Шаблон страницы компонента

Порядок отражает **частоту обращения**, а не полноту: большинство визитов
заканчивается на первом экране.

```
  Имя компонента                              [Стабильно] v0.x
  Одна строка: какую работу делает
──────────────────────────────────────────────────────────────
  1. ЖИВОЙ ПРИМЕР        демо · [Разметка ▾] · [⧉ Копировать]
                         переключатели темы и плотности
  2. УСТАНОВКА           одна строка, всегда одинаковая
  3. КОГДА / КОГДА НЕ    две колонки: ✓ используйте · ✗ возьмите [X]
──────────────────────────────────────────────────────────────
  4. ВАРИАНТЫ            каждый — демо + разметка
  5. РАЗМЕРЫ             sm / md / lg
  6. СОСТОЯНИЯ           сетка всех состояний
  7. С ИКОНКОЙ           слева / справа / только иконка
  8. КОМПОЗИЦИИ          в группе, в тулбаре, в форме
──────────────────────────────────────────────────────────────
  9. СПРАВОЧНИК          таблицы: классы · разметка · переменные ·
                         токены · data-атрибуты
 10. ДОСТУПНОСТЬ         таблица клавиш · роли · что даёт приложение
 11. ПОЧЕМУ ТАК          ← существующие .why переезжают СЮДА
 12. СВЯЗАННОЕ           + ссылка на исходник с номером строки
```

**Одно решение здесь принципиально: `.why` уезжает вниз.** Тексты превосходны,
но сейчас стоят **перед** демо и между читателем и его задачей. Кто пришёл за
кнопкой — получает кнопку; кто пришёл понять систему — доскроллит. Это не
понижение их ценности, а признание, что у страницы два читателя с разной
частотой обращения.

**Готово, когда:** любой компонент можно применить, не открывая `src/*.css`.

### Результат

**71 страница. Покрытие 267 из 267 классов — 100%.** `docs-check` говорит
«документация и кит сходятся полностью»: ни одного выдуманного класса, токена
или значения атрибута, ни одной битой ссылки.

Из 71 страницы 41 написана четырьмя агентами параллельно, 30 — вручную.
Разделение по признаку: там, где ценность страницы в сравнении с соседями
(агентный слой, ядро полей), писал сам; где страница механична — перенос
токенов и правил в таблицы — отдал агентам.

**Проверка выросла трижды, и каждый раз по факту найденной ошибки:**

| Что проверяет | Что нашла |
|---|---|
| Классы в обе стороны | Первый же сочинённый пример разметки в README потерял обязательные роли |
| Битые ссылки | 25 ссылок на ненаписанные страницы — список работал планом работ |
| Значения `data-атрибутов` | Опечатка в значении выглядит как базовое значение и молча ничего не делает |
| Имена токенов | `--log-level`, которого не существует: класс называется `inst-log-level` |

Последнее стоит отдельного слова. Выдуманный токен нем так же, как выдуманный
класс: `var()` от несуществующего имени молча отдаёт пустоту, и страница врёт
беззвучно. Проверка знает две законные формы записи, которые токенами не
являются, — модификатор класса в прозе (`--danger`) и сокращение семейства
(`--space-*`), — поэтому из 275 первых срабатываний осталось одно, и оно было
настоящим.

**Голос выдержан.** Конструкция «X, а не Y» встречается на 68 страницах из 70,
числа-доводы на 51, вступления от 62 до 228 знаков при медиане 145. Агенты
попали в тон по двум эталонам.

    actions · inputs · display · charts · navigation ·

/agent/                  ←СЕКЦИЯ ВЕРХНЕГО УРОВНЯ, а не подраздел
    overview · task · step · approval · failure · diff ·

                         design-principles ←docs/about/design-principles.md переезжает сюда
```

Пять решений, отличающих это от нынешней структуры:

1. **Foundations, а не Tokens** — сюда ходят дизайнеры, слово «токены» их отсекает.
2. **Agent — верхний уровень.** Это то, ради чего кит стоит брать: `.task`,
   `.step`, `.approval`, `.failure`, `.diff`, `.lane`, `.budget` нет ни у
   shadcn, ни у Radix, ни у Mantine, ни у MUI, ни у Ant Design.
3. **Patterns существует.** Сейчас нет ни одного собранного экрана.
4. **Accessibility — секция**, а не примечания в `.why`.
5. **Density в Foundations.** Одна из двух уникальных архитектурных идей кита
   сейчас существует как безымянный переключатель в шапке.

**Готово:** у каждого компонента свой URL, работает поиск, живые примеры
рисуются настоящим китом.

### Результат

**73 страницы, 127 живых примеров, поисковый индекс Pagefind, битых ссылок
нет.** Проверяется машинно: `node tools/site-check.mjs`.

Сайт лежит в `site/`, контент — по-прежнему в `../docs`. Это не удобство, а
условие: относительные ссылки вида `./button.md` обязаны работать и при чтении
репозитория, и на сайте. Ради этого же конституция переехала в
`docs/about/design-principles.md` — файл вне контента ломал бы 73 ссылки.

**Сборка появилась только у документации.** Кит остаётся подключаемым одной
строкой, и `sync-kit.mjs` копирует его в `public/` как есть, не пропуская через
Vite: сайт обязан показывать ровно тот CSS, который получит потребитель, а не
его сборочный пересказ.

### Три поломки, которых не видно на глаз

Каждая оставляла страницу внешне целой, и каждая найдена машиной, а не
просмотром.

**Ссылки не переписывались в маршруты.** Все 73 страницы ссылались друг на
друга путями к `.md`, и на сайте каждая вела в 404. Лечится плагином remark,
который считает маршрут от пути файла, а не от текущего URL.

**Starlight выигрывал у кита по порядку слоёв.** В слое `starlight.content`
объявлено `.sl-markdown-content :is(img, …, svg, …) { height: auto }`, и внутри
сцены иконки вырастали до 150px — дефолтной высоты SVG без атрибутов. Это
прямое следствие главного обещания кита «стили приложения всегда выигрывают»:
приложением здесь оказался сам движок документации. `revert-layer` не помогает —
он откатывает к слою Starlight. Размеры возвращены поимённо: SVG-компонентов в
ките ровно четыре.

**Спрайт иконок нельзя положить в `<head>`.** `<use href="#i-refresh">` ищет
символ в том же документе, а символы внутри `<head>` браузер не отдаёт.
Переопределён `Header`, спрайт вшивается через `?raw` — читать его в рантайме
нельзя: после бандлинга `import.meta.url` указывает на чанк, а не на исходник.

### Осталось решить

- [ ] **Судьба `index.html`.** Живая спецификация была тестом покрытия, но эту
      работу теперь делает `docs-check` (100% классов), а показ — сайт. Она
      остаётся единственной сборкой всех компонентов на одном экране и
      единственным демо без сборки. Либо переезжает в `/patterns` этапа 6,
      либо становится страницей «всё разом», либо уходит.
- [ ] **3.5. Английская версия.** Отложена: i18n в Starlight заложен
      (`defaultLocale: root`), но перевод 73 страниц — отдельная работа.
- [ ] **Домен и публикация.** Этап 10.

## Этап 4. Клавиатура

**Срок: 2 недели.**

`docs/about/design-principles.md:243` честно выносит бегущий `tabindex` в слой приложения. Но
следствие: `.task`, `.tree`, `.segmented`, `.menu`, `.tabs` в поставке
**недоступны с клавиатуры вообще** — `role="listbox"` без `tabindex` не
получает фокус.

Это хуже, чем «не сделано». Кит навязывает ARIA-роли и завязывает на них стили;
`role="listbox"` — обещание скринридеру, что стрелки работают. Компонент,
объявляющий роль и не выполняющий её контракт, обманывает вспомогательную
технологию.

- [ ] **4.1.** `packages/core/behavior/roving.js` — на основе уже написанной и
      корректной `wireRadioGroup` из `index.html`. Покрыть listbox, tree, menu,
      tabs. ~200 строк, автоинициализация по ролям, полностью опциональная.
- [ ] **4.2.** Touch targets. WCAG 2.2 AA требует 24×24. Провалы:
      `.tag-remove` — интерактивная кнопка `--size-chevron`, то есть **10×10 во
      всех плотностях**; в `compact` всё размеренное `sm`/`xs` уходит ниже
      нормы (`--control-h-sm: 22px`, `--control-h-xs: 18px`).
      Чинить областью нажатия через `::before { inset: -7px }` — форма не
      меняется, цель вырастает.
- [ ] **4.3.** `tools/targets.mjs` — проверка целей по всем трём плотностям,
      рядом с контрастом.
- [ ] **4.4.** Раздел Accessibility: заявить WCAG 2.2 AA, таблица клавиш по
      компонентам, отчёт контраста прямо на странице.

**Готово, когда:** каждая объявленная роль выполняет свой контракт, и это
проверено машиной.

Два замечания к разбиению:

**`components.css` — 1049 строк**, и внутри всё: кнопки, панели, таблица со
всеми расширениями, метрики, мера, скелетон, баннер, аккордеон. При 100
компонентах это 3000 строк. Таблица — самый сложный компонент кита — заслуживает
своего файла.

**Три файла в одном слое.** `kit.css` кладёт `components.css`, `forms.css` и
`data.css` в `kit.components`. Правило «порядок объявлен явно, поэтому
фиксирован» (`docs/about/design-principles.md:324`) внутри этого слоя не действует — три файла по
1049/656/281 строк соревнуются по специфичности и порядку импорта.

## Что осознанно НЕ делается

Чтобы через месяц не спорить заново:

- **Паритет по числу компонентов** с MUI/AntD. Проигрышная гонка, уничтожающая
  дифференциатор.
- **Утилиты отступов** (`mt-3`, `p-2`). Запрещены `docs/about/design-principles.md:349`, и причина
  там верная.
- **Второй акцентный тон.** `docs/about/design-principles.md:108`.
- **Брейкпоинты как шкала.** Порядок интринсик → `@container` → `@media`
  (`docs/about/design-principles.md:332`) архитектурно правильнее для панельного кита. Но **порог
  контейнерного запроса надо назвать токеном** — сейчас он вписан числом.
- **Карусель.** `docs/internal/SCOPE.md:54`, дашбордам не нужна.
- **Сборка для подключения кита.** Одна строка `<link>` — реальное
  преимущество, его надо сохранить. Сборка появляется только у Svelte-слоя.
