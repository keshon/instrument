# Что дальше

Личный проект. Список короткий намеренно: длинный план для кита, который
пишется по вечерам, — это способ не работать над китом.

## Хочется

- **Перевести документацию на английский.** Генератор двуязычен, механика
  готова; собирается один язык, пока переводить нечего показывать.
- **Комбобокс и автодополнение.** Единственное, чего заметно не хватает при
  сборке настоящего экрана.
- **Выбор даты сверх нативного.** Календарь есть, поведения к нему нет.
- **Разбить `components.css`.** 1 200 строк: кнопки, панели, таблица,
  метрики, мера, скелетон, аккордеон в одном файле. Таблица заслуживает
  своего.
- **Разделитель панелей с перетаскиванием.** Сплит есть, ручки у него нет.
- **Виртуализация длинных логов и очередей.** Сейчас это честно слой
  приложения, но у кита нет и подсказки, как её делать.
- **Тон голоса в документации.** Слишком однообразный; правится по странице
  за раз, когда она и так открыта.

## Не делается

Чтобы не спорить об этом заново:

- **Паритет по числу компонентов** с MUI и Ant Design. Гонка, в которой этот
  кит проигрывает по определению, и ради неё пришлось бы выбросить то,
  из-за чего его вообще стоит брать.
- **Утилиты отступов** (`mt-3`, `p-2`) — запрещены
  [конституцией](docs/about/design-principles.md).
- **Второй акцентный тон.**
- **Сборка для подключения кита.** Одна строка `<link>` — главное удобство,
  и терять его не за что.
- **npm-пакет.** Копирование файла или сабмодуль. Публиковаться незачем.

## Как оно проверяется

Всё, что можно проверить машиной, проверяется на каждый push:

```bash
go -C tools run ./cmd/contrast    # контраст в шести темах
go -C tools run ./cmd/targets     # цели нажатия в трёх плотностях
go -C tools run ./cmd/docscheck   # документация против кита, в обе стороны
go -C tools run ./cmd/dist -check # dist сходится с src
go -C site  run ./cmd/site        # сборка сайта роняет себя сама
```
